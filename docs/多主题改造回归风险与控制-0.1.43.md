# MarkHunter 多主题改造（Tailwind v4 + daisyUI v5）回归风险与控制方案

- 目标版本：0.1.43（下一版本）
- 方案：方案A —— Tailwind CSS v4（CSS-first）+ daisyUI v5 作为主题引擎，`<html data-theme="xxx">` + daisyUI 主题令牌，30+ 内置皮肤 + 自研「经典」皮肤，设置面板新增「主题」下拉。
- 本文只读分析，未改任何代码。基线：`npm run smoke` 现有 94 项全过（11 项 API/主进程直测 + 80 项 UI step + 2 项剪贴板片段），bundle.js ≈ 9.1MB（9,548,466 B），styles.css ≈ 30KB（30,681 B），本机 Node v24.18.0 / npm 12.0.1，CI 为 Node 20 + windows-latest。

---

## 0. 结论摘要

1. **94 项冒烟断言中没有一项直接断言「颜色」**；与样式/布局相关的只有 4 项探测型用例（`caretVisible`、`userSelect`、`scrollbarSetting`、几何系 `divider*`/`viewerScrollFull`/`selectSameLine`）。在「加载顺序正确 + 语义类名不改 + 关键规则保持字面量」三条红线约束下，**预期 0 项必然失败**；真正的失败风险来自重构动作本身（改名、移动规则、改类名），而非 tailwind/daisyUI 的引入。
2. **唯一必须处理的硬冲突是 CSS 变量 `--border` 同名**：styles.css 用它存「边框颜色」（`#e3e8ef`），daisyUI v5 用它存「边框宽度令牌」（`1px`）。必须重命名 MarkHunter 侧变量，并保证 tailwind.css 先于 styles.css 加载。
3. **preflight 会真实改变视觉的清单很短**：预览列表 `list-style` 丢失（ul/ol 被重置为 none）、全局 `line-height` 从 UA normal 变 1.5、`button`/`select` 变透明底 + 圆角归零、`img` 变块级。均可一行 CSS 兜底，且不影响任何几何断言。
4. **构建链零侵入**：`tailwind.css` 作为构建产物输出到已被 `dist/` 规则忽略的 `src/renderer/dist/`，由 `scripts/build.js` 内嵌生成步骤产出，index.html 增加一个 `<link>`；`release.yml`（`npm ci` + `node scripts/build.js`）**无需改动**。
5. **体积可忽略**：全量 35 主题 + preflight + daisyUI 组件层 ≈ 未压缩 50–90KB / 压缩 15–35KB，不足 9.1MB bundle 的 1%，首屏解析 <5ms。
6. **依赖兼容**：Tailwind v4 要求 Node ≥20（本机 24 ✓、CI 20 ✓）；daisyUI v5 仅兼容 Tailwind v4；v4 输出含 oklch/color-mix/@property，Electron 43（Chromium ≥140）完整支持。建议精确锁定版本。

### 1.2 判定与三条「改动红线」

**判定：在正确实现下，94 项现有断言无需修改即可全绿。** 会挂的只会是「重构动作」导致的，因此把控制点写成红线：

1. **不改语义类名**：`.tab` `.tab.pinned` `.tab-pin` `.selected` `.tree-node` `.caret.open` `.caret.leaf` `.current` `.hidden` `.ctx-item` `.find-result` `.gs-group` `.tbtn` `.ptab` `.markdown-body` `.mermaid-wrap` `.viewer-stage` `.viewer-img` `.image-tab-img` `.fav-item` `.ai-model-select` 等一律保留（多主题只换「颜色/令牌」，不换「结构/类」）。
2. **`.cm-cursor` 规则保持顶层字面规则**：`visibility: visible !important` 不得移入 `@media`/`@layer`/变量间接（否则 `caretVisible` 的顶层 cssRules 扫描找不到）；若将来必须嵌套，同步把该用例改成「递归遍历 cssRules」。
3. **`--scrollbar-width` 保持定义在 `:root`**，且 app.js 启动内联覆盖逻辑不变（`scrollbarSetting` 依赖语义：API 直改不同步、面板保存才同步）。

### 1.3 需要的断言修正建议（尽量不削弱意图）

- **对现有 94 项：不建议改动任何断言**（包括几何容差，现有 ±10/±6px 容差已足够）。
- **建议新增 2 项**（补上新功能且不削弱旧意图）：
  1. `themeRoundTrip`：`api.setSettings({theme:'dark'})` → `getSettings().theme === 'dark'`（验证设置白名单/持久化，仿 `scrollbarSetting` 模式，说明 API 直改不即时同步 UI）；再走设置面板保存流程 → 断言 `document.documentElement.dataset.theme` 生效（验证 `openSettings` 的 patch 与 `applyTheme` 接线）。
  2. `previewListStyle`（可选，正好补上 preflight 视觉盲区）：打开 md 后 `getComputedStyle(document.querySelector('.markdown-body ul')).listStyleType !== 'none'` —— 防止预渲染列表无项目符号回归。
- **保留意图的兜底**：`caretVisible` 若因重构必须嵌套规则，把扫描改为递归 `cssRules`（含 `@media` 内规则）即可，断言语义不变。

### 2.1 关键冲突（必须处理）

### 2.2 无冲突（preflight 与现有手写规则一致的部分）

- `*{box-sizing:border-box;margin:0;padding:0;border:0 solid}` ≡ styles.css:19 → **几何断言安全的前提**。
- `body{margin:0;line-height:inherit}` ≡ styles.css body。
- `table{border-collapse:collapse}` ≡ styles.css:793；`hr` 重置被 `.markdown-body hr`(L810) 覆盖；`a{color:inherit}` 被 `.markdown-body a`(L755)/`.py-cand`(L732) 覆盖；`code/pre` 字体被 `.markdown-body code/pre`(L769-791) 覆盖；`textarea{resize:vertical}` 被 `.ai-input-row textarea{resize:none}`(L1080) 覆盖；`[hidden]{display:none!important}` 与 `.hidden` 类(L516) 无关（应用全用 `.hidden` 类，不用 hidden 属性，已核对 index.html）。
- **`--scrollbar-width`**（L707）：daisyUI 无同名令牌，无冲突。

### 2.3 加载顺序与 @layer 建议

- **推荐：`<link href="dist/tailwind.css">` 在前，`<link href="styles.css">` 在后**（index.html head）。理由：
  - preflight 作为最底层「重置」，MarkHunter 规则后加载、同特异性自然覆盖（如 html/body 规则）；
  - daisyUI `[data-theme]` 与 `:root` 特异性相同 → 后加载的 styles.css 保证 MarkHunter 变量（`--bg`/`--text`/`--accent` 等）胜出；
  - CSP `style-src 'self' 'unsafe-inline'` 对外部样式表无限制，`data-theme` 是属性不是内联样式，均合规。
- **0.1.43 不建议把 styles.css 并入 `@layer`**：未分层样式优先级高于所有 `@layer` 内样式，若把 MarkHunter 规则放进 `@layer components`，preflight（layer 外 base）反而会压过它，必须给关键规则加 `!important` 或提高特异性，徒增风险。保持 styles.css 为非 layer 静态文件最稳。
- 若后续想统一管道再评估 `@import "tailwindcss" layer(theme, base, components, utilities);` 显式分层方案。

### 2.4 多主题生效的前提：MarkHunter 变量桥接（本方案核心工作量）

styles.css 用的是自有变量，与 daisyUI 令牌（`--color-base-*`/`--color-primary`/`--color-error` 等）**不同名、不联动**。要让切换 `data-theme` 真正改变 MarkHunter UI，必须在 `:root` 做一层桥接（vars 引用 vars，`var()` 解析不受特异性影响，daisyUI 令牌定义在 `<html>` 上即可被引用）：

```css
:root {
  --bg:          var(--color-base-200);      /* 经典: #f5f7fa */
  --bg-panel:    var(--color-base-100);      /* 经典: #ffffff */
  --bg-hover:    var(--color-base-300);      /* 经典: #eef2f7 */
  --bg-active:   color-mix(in oklab, var(--color-primary) 14%, var(--color-base-100));
  --text:        var(--color-base-content);  /* 经典: #26303e */
  --text-2:      color-mix(in oklab, var(--color-base-content) 62%, var(--color-base-100));
  --accent:      var(--color-primary);       /* 经典: #3b82f6 */
  --accent-2:    var(--color-secondary);     /* 经典: #14b8a6 */
  --danger:      var(--color-error);         /* 经典: #e5484d */
  --radius:      var(--radius-field);        /* 经典: 8px */
  --mh-border:   var(--color-base-300);      /* ← C1 重命名后的边框颜色 */
}
```

- 「经典」皮肤 = 用 MarkHunter 现有调色板定义一个 daisyUI 自定义主题并设为 `--default`（无 data-theme 时也生效，杜绝空白闪屏）。
- **硬编码色残留盘点**（不桥接则深色主题下这些区域不变色，需按优先级替换为 `var(--color-*)` 或 color-mix）：`.tbtn` 白底（L90）、`.tbtn.accent` 渐变（L99）、`.brand-mark` 渐变（L70）、`.fav-block`/`#sidebar-search` `#fbfcfe`（L164/L244）、各 input/textarea 底色 `#fbfcfe`（L259/L589/L669/L1084）、`.modal`/`.ctx-menu` 白底（L652/L687）、`.preview-host` 白底（L499）、`.image-host #f2f4f7`（L434）、`.markdown-body` 系列（L736-816，正文色/链接/代码/表格）、`.py-output #1e2430`（L626，**深底亮字，深色主题下天然可读，可保留**）、`.toast` 深色（L714）、`.zoom-badge` 深色（L868）、`.viewer-stage #f6f8fa`（L906）、`.cm-gutters`（L522）、选中高亮 `#cfe3ff`（L525-529）、滚动条滑块 `#cbd5e1`（L709）、搜索 mark 高亮 `#ffe08a`（L321/L606）、`.ai-msg.system`（L1044）、`.mermaid-wrap` 白底（L823）。

## 3. 构建链改动与 CI 影响

### 3.1 build.js（唯一的构建链改动点）

在 esbuild 之外增加一步 Tailwind 编译（顺序无关）：

```js
const { spawnSync } = require('child_process');
// ① 编译主题 CSS（用 node 直调 CLI，避免 npx 联网/首装提示）
const css = spawnSync(process.execPath, [
  require.resolve('@tailwindcss/cli/dist/index.mjs'),
  '-i', path.join(__dirname, '../src/renderer/tailwind.input.css'),
  '-o', path.join(__dirname, '../src/renderer/dist/tailwind.css'),
  '--minify', // 可选：与 esbuild minify:false 保持一致则去掉
], { stdio: 'inherit' });
if (css.status !== 0) process.exit(css.status);
// ② 现有 esbuild 步骤不变
```

- `tailwind.input.css`（**提交进仓库**，内容：`@import "tailwindcss";` + `@plugin "daisyui" { themes: ... }` + `:root` 桥接段 + 兜底规则）。
- `dist/tailwind.css`（**构建产物，不提交**）。
- `npm start` 需先 `npm run build` —— 与现状一致（bundle.js 同样在 dist/、被 gitignore），无新增约束；在 README/开发说明中注明即可。

### 3.2 文件落位与 .gitignore

- 输出放 **`src/renderer/dist/tailwind.css`**：已被 `.gitignore` 第 3 行 `dist/`（匹配任意层级同名目录）忽略，**无需修改 .gitignore**；index.html 用 `<link rel="stylesheet" href="dist/tailwind.css">`，与 `<script src="dist/bundle.js">` 同构。
- 备选：输出到 `src/renderer/tailwind.css` 则需在 .gitignore 加一行 —— 不推荐，徒增改动。
- **不要**把 tailwind.css 提交进仓库：产物由构建生成，提交会产生「忘记重新构建导致样式过期」的漂移源。

### 3.3 package.json / 依赖

- devDependencies 增加：`tailwindcss`（^4.x）、`@tailwindcss/cli`（与 tailwindcss 同版本）、`daisyui`（^5.x）；`npm install` 更新 package-lock.json（已提交，`npm ci` 确定）。

## 4. 体积与性能

| 项 | 估算 | 说明 |
|---|---|---|
| preflight | ≈ 2–3KB | v4 现代 reset（含 color-mix 占位符等） |
| daisyUI 35 主题 | ≈ 35–45KB（未压缩）/ 10–15KB（压缩） | 每主题 ≈1KB（`--color-*` + color-scheme） |
| daisyUI 组件层 | ≈ 15–40KB | 未用组件类也会输出；可用 `@plugin "daisyui" { exclude: [...] }` 裁掉，只留 themes |
| **tailwind.css 合计** | **≈ 50–90KB 未压缩 / 15–35KB 压缩** | 相对 9.1MB bundle 占比 **<1%** |
| 首屏影响 | CSS 解析 <5ms（Chromium 现代引擎）；多一个 file:// 本地 `<link>` 读取（微秒级） | CSS 是 render-blocking，但绝对量极小 |
| 主题切换 | `data-theme` 属性切换 = 仅换 CSS 变量 → 颜色 repaint，无重排/重绘大面积开销 | 设置面板内 onChange 即时预览，保存才持久化 |

**全主题 vs 子集**：需求是 30+ 皮肤 → 全量 35 主题一次打进 CSS（几十 KB 代价完全可接受）；**不建议运行时动态加载主题 CSS**（增加 file:// 异步加载、闪烁与 CSP/file 权限复杂度）。建议裁剪 daisyUI 组件层（exclude 未用组件组）以把体积压到最小，但这不是必需项。

## 5. 依赖安全与版本

| 项 | 结论 |
|---|---|
| Tailwind v4 Node 要求 | **Node ≥20**（本机 24.18 ✓，CI setup-node 20 ✓）；`@tailwindcss/oxide` 平台二进制自动安装（win32-x64-msvc） |
| daisyUI v5 | **仅兼容 Tailwind v4**（CSS-first `@plugin "daisyui"`，无 JS 配置）；与 v3 不兼容 —— 本方案全新引入，无迁移问题 |
| 与 Electron 43 的关系 | 无直接关联；但 v4 输出使用 oklch / color-mix / @property 等现代 CSS，**Electron 43（Chromium ≈140+）完整支持**；esbuild `target: chrome120` 只影响 JS 转译，与 CSS 无关 |
| 版本锁定 | 建议 **精确锁定**（`"tailwindcss": "4.1.x"`、`"@tailwindcss/cli": "4.1.x"`、`"daisyui": "5.0.x"` 去掉 caret 或依赖已提交的 package-lock.json）。CSS 产物跨小版本可能变化，精确锁定 + 记录产物哈希可保证字节级稳定与回归可比 |
| 供应链面 | 两者均为 devDependencies（构建期），不进 asar 运行时（bundle.js 已内联，mermaid 同属 devDeps 先例）；安装走 registry.npmjs.org（本机可达） |
| 已知坑 | ① 构建脚本禁用 `npx`（首跑可能联网交互）→ 用 `node <cli-mjs>` 直调；② v4 自动内容探测从 CSS 文件目录向上扫描，若后续用工具类，确认 `src/renderer/*.js` 在扫描范围内（含生成物 dist/ 无妨）；③ daisyUI v5 的主题变量若与业务冲突见 C1 |

## 6. 回归验证流程

每阶段门槛：`node scripts/build.js` → `npm run smoke` 全绿，且执行手工清单。

| 阶段 | 内容 | 门槛 |
|---|---|---|
| P1 纯引入 | 加依赖 + build.js 生成 dist/tailwind.css + index.html 引 link（**暂不接主题**，default=经典） | smoke 94 全绿；经典皮肤与基线**像素级无差异**（重点目检 §2.4 硬编码色是否被动） |
| P2 变量桥接 | `:root` 桥接段 + `--border`→`--mh-border` 重命名 + preflight 兜底（列表符号/行高/按钮 cursor） | smoke 94 全绿；经典皮肤与基线近似（border 重命名后逐处核对无丢边框） |
| P3 多主题 | 经典自定义主题（`--default`）+ settings.js 白名单（`DEFAULTS`+`ALLOWED_KEYS` 都加 `theme` 键）+ openSettings 主题 `<select>` + `applyTheme`（`documentElement.dataset.theme`）+ 保存 patch 接线 | smoke 94 全绿 + 新增 `themeRoundTrip`/`previewListStyle` 用例；35 主题可切换、重启持久化 |
| P4 打包验证 | `npx electron-builder --win --dir` → 检查 asar 含 dist/tailwind.css；打 tag 走 CI（release.yml 无需改） | 安装包可运行、主题正常；CHANGELOG 记 0.1.43 |

**手工回归清单（各主题下 UI 可读性，至少抽查 8 个代表：经典 / light / dark / cupcake / synthwave / dracula / night / retro / black）**：
1. 工具栏按钮（含 `.tbtn.accent` 渐变）文字与 hover 态可读；
2. 文件树选中态（`.tree-node.selected`）与 hover 对比度；
3. 标签页 active/pinned（渐变底 + 强调左边框）可辨识；
4. 预览：标题层级、列表符号（C2 回归）、行内 code、代码块、表格、blockquote、hr；
5. 图片查看器与图片标签页背景、滚轮缩放后滚动条可见性；
6. 文件内搜索/全局搜索高亮（`mark` 底色 `#ffe08a` 在浅色主题外的观感）；
7. AI 侧栏消息气泡、模型徽标、输入框；
8. 弹窗/右键菜单/Toast/状态栏；
9. Python 输出面板（固定深色底，确认亮/暗主题下均可读）；
10. 滚动条滑块颜色对比度（`--scrollbar-width` 6/10/40 三档）；
11. 原生控件（checkbox accent-color、select 下拉）随主题正常。
