# MarkHunter 0.1.43 主题引擎映射方案 —— 现有 UI → daisyUI 令牌 → 一键换肤

> 状态：调研完成（只读，未改代码）。基线：daisyui **5.7.18**（源码核实，`packages/daisyui/theme/object.js`）、tailwindcss **4.x**、Electron **43.3.0**（Chromium ≈142，支持 `oklch` / `color-mix` / `@layer` / `:has`）。
> 本方案聚焦「映射准确性 + 改造清单 + 经典皮肤注册」，是对 `docs/开发计划-主题设置与用户体验.md`（下称《既有计划》）的**修订与补全**；两处文档冲突处以本文为准。

## 0. 结论速览（含对《既有计划》的勘误）

1. **内置主题实为 34 种，不是 32 种**（《既有计划》§0.1 数错）。源码 `theme/object.js` 枚举：abyss、acid、aqua、autumn、black、bumblebee、business、caramellatte、cmyk、coffee、corporate、cupcake、cyberpunk、dark、dim、dracula、emerald、fantasy、forest、garden、halloween、lemonade、light、lofi、luxury、night、nord、pastel、retro、silk、sunset、synthwave、valentine、winter、wireframe —— 共 **34**。加 `markhunter-classic` = **35 种皮肤**，正好满足任务书「30+ 内置 + 经典 = 35+」，**无需**再自研 2 种凑数（暗色/纸感皮肤可作 0.1.44+ 增强）。
2. **⚠️ 命名冲突（《既有计划》未发现，必改）**：daisyUI 主题块里的 `--border` 是**边框宽度令牌**（默认 `1px`），而 MarkHunter 的 `--border` 是**边框颜色**（`#e3e8ef`）。若把 MarkHunter 颜色变量沿用 `--border` 名，主题块输出（`[data-theme="x"] { --border: 1px }`）会把全应用 `var(--border)` 变成 1px 颜色值 → 所有边框崩色。**必须把 MarkHunter 语义变量统一改名加 `--mh-` 前缀**（`--mh-border`、`--mh-bg`、`--mh-accent`…），一次性重命名，一劳永逸避开 daisyUI / Tailwind / 未来变量命名空间。
3. **`@plugin "daisyui"` 会无条件打包全部组件 CSS**（v5 源码 `index.js`：base+components+utilities 全量 `addComponents`，无 `components:false` 选项，约 300KB+ 未压缩）。MarkHunter 组件全部手写、不消费组件类，纯主题用途下可用 **`@plugin "daisyui/theme"` 块逐个注册主题**（源码确认：`name` 命中内置主题时自动合并内置令牌），完全跳过 `@plugin "daisyui"` → 零组件 CSS。0.1.43 建议先走文档标准路径 `@plugin "daisyui" { themes: all; }`（低风险），体积优化作为可选收尾（见 §6）。
4. **`daisyui/theme` 插件透传任意自定义变量**（源码 `theme/index.js`：`const { name, default, prefersdark, "color-scheme", root, ...customThemeTokens } = options`，随后 `themeTokens = { ...customThemeTokens }` 全量输出到 `[data-theme]`）→ MarkHunter 扩展令牌（`--mh-bg-hover`、`--mh-accent-soft` 等）可**直接写进每个主题块**，随 `data-theme` 一起切换。这是「经典皮肤逐像素一致」的关键能力。
5. **映射架构分三层**（§3）：daisyUI 令牌（每主题）→ 通用推导层（`:root` 的 color-mix 公式，对所有内置主题自适应）→ 经典精确层（经典主题块内写死现状 hex，像素一致）。
6. 默认皮肤名沿用《既有计划》的 **`markhunter-classic`**，`default: true`，老用户观感零变化。

## 2. daisyUI v5 主题机制（源码级核实）

1. **主题令牌集**：每个主题 = 一组 CSS 变量，挂到 `[data-theme="x"]`（default 主题还挂 `:where(:root)`）：
   `--color-base-100/200/300`（背景梯度）、`--color-base-content`（正文）、`--color-primary/secondary/accent/neutral` + 各自 `-content`、`--color-info/success/warning/error` + 各自 `-content`、`--radius-selector/field/box`、`--size-selector/field`、`--border`（**宽度**！）、`--depth`、`--noise`、`color-scheme`。
2. **`@plugin "daisyui" { themes: all; }`** 行为（源码 `pluginOptionsHandler.js`）：light 以 `:where(:root)` 默认应用；dark 以 `@media (prefers-color-scheme: dark)` 的 `:root:not([data-theme])` 应用；其余 32 个以 `[data-theme=x]` 输出。**只要 `<html>` 始终显式带 `data-theme`，默认/prefersdark 分支不生效**（`:where()` 零特异性、`:not([data-theme])` 被属性排除）→ 手动换肤 100% 可控。
3. **`@plugin "daisyui/theme"` 块**（源码 `theme/index.js`）：`{ name, default, prefersdark, "color-scheme", root, ...customThemeTokens }` —— **任意 `--x` 自定义变量全量透传**；`name` 命中内置主题时 `{ ...内置令牌, ...自定义令牌 }` 合并。因此：① 经典皮肤块可写死精确 hex（含 `--mh-*` 扩展令牌）实现像素一致；② 只注册主题、不引主插件，可零组件 CSS。
4. **`color-mix(in oklab, a b%, c)`** 用于从核心令牌推导浅染/降饱和色；Chromium ≥111 支持，Electron 43 无虞。

### 3.2 三层结构落地位置

```
Layer 0  daisyUI 主题块（Tailwind 产物 dist/theme.css）
        --color-base-100/200/300、--color-primary…、--radius-*、--border(宽度)…
Layer 1  通用推导层  theme.css 的 `:root`（手写，无 @layer → 天然压过 daisyUI 的 @layer base 内同名变量）
        --mh-accent: var(--color-primary); --mh-bg: var(--color-base-200); …（color-mix 公式）
Layer 2  经典精确层  markhunter-classic 主题块内的 --mh-* 精确 hex（随 data-theme 切换，覆盖 Layer 1）
Layer 3（可选） 内置主题微调  styles.css 或 theme.css 追加
        [data-theme="night"] { --mh-bg-hover: …; }   /* 个别主题定向修正 */
```

### 4.2 不改（设计意图固定，明暗主题均成立）

| # | 组件 | 理由 |
|---|---|---|
| 1 | `.toast` / `.zoom-badge` | 半透明深色浮层，明暗主题下均为最高对比（与 VS Code 通知一致） |
| 2 | `.py-output` / 预览 `<pre>` / AI 气泡内 `<pre>` | 终端/代码块语义色 `#1e2430`，明暗主题下均可读，**保持固定深色**（可选二期做「代码块跟随明暗」，非本期） |
| 3 | PDF `<embed>` | Chromium 内置 PDF 查看器，不受页面 CSS 影响 |
| 4 | 原生窗口边框/菜单/原生滚动条 track | 跟随系统 `color-scheme`（daisyUI 每主题自带 `color-scheme`，暗色主题自动生效） |
| 5 | `--mono` 字体栈、布局/尺寸/间距 | 与颜色无关 |

### 4.3 需要「重写为 Tailwind utility」吗？—— 不需要

- 结论：**全部手写 CSS 保留**，只做「硬编码色 → `var(--mh-*)`」替换。理由：
  1. 组件样式含大量布局/交互细节（拖拽分隔条、树懒加载、滚动同步、图片缩放），utility 化是纯增量风险；
  2. daisyUI 组件（`btn`、`menu`、`modal`…）与现有 `.tbtn`/`.tree-node` 视觉协议不同，引入后反而要重调间距/圆角/高度，得不偿失；
  3. 唯一可能新增 utility 的场景是**未来新增组件**（Fluent 二期）或设置面板新控件复用 `.field-select`（抽取自 `.ai-model-select` 的通用类，仍是手写 CSS）。
- 因此本方案的 daisyUI 定位 = **纯主题引擎**（令牌 + data-theme），不消费任何组件类。

## 6. 分阶段实施建议（增量映射）

### 阶段 1（0.1.43 主体）：UI 骨架全面跟随主题 —— 推荐先做

范围：
1. 构建链路：`package.json` devDependencies 增 `tailwindcss@^4`、`@tailwindcss/postcss@^4`（或 `@tailwindcss/cli`）、`daisyui@^5`、`postcss@^8`；新增 `postcss.config.js`、`src/renderer/theme.css`、`scripts/build-css.js`；`npm run build` 串行化（JS → CSS）；`index.html` head 加 `<link rel="stylesheet" href="dist/theme.css">`（置于 `styles.css` 之前）。
2. 令牌层：§5 的 theme.css（34 内置 + markhunter-classic + Layer 1 推导层）。
3. styles.css 变量化：`--mh-*` 改名 + §4.1 全部硬编码替换（最大单项，逐区核对）。
4. 主进程：`settings.js` 加 `themeName`（`ALLOWED_KEYS` + `DEFAULTS` + 值域校验，THEME_NAMES 集）；新建 `src/main/themes.js`（与渲染进程共享清单，含 DARK_THEMES）；`main.js` `backgroundColor` 按明暗取色；preload 首帧设置 `data-theme`（`ipcRenderer.sendSync('theme:get-sync')` 一次性，或 `additionalArguments` 传参二选一）；`index.html` `<html data-theme="markhunter-classic">` 作无 JS 兜底。
5. 渲染进程：`app.js` `applyTheme(name)`（设 `documentElement.dataset.theme`，暴露到 `window.__app`）；boot 初始化时应用已存主题；`openSettings()` 加「主题」下拉（optgroup 分组 + change 即时预览 + 取消还原，复用 `.field-select` 通用类）。
6. CodeMirror 表层 + JS 主题 var() 化（§4.1 #16/#17）—— 背景/文字/光标/gutter/选区/活动行跟随主题；**语法高亮色保持默认浅色**（P2 处理）。
7. 冒烟：新增 ~7 条（default/applyDirect/applyViaUI/persist/whitelist/catalog/restore，见《既有计划》§6）+ 94 项回归全绿。
8. 收尾：`index.html` 无内联脚本（CSP 不变）、CHANGELOG、版本 0.1.43。

**理由（为什么编辑器/预览/图表放 P2）**：
- P1 全部是「变量引用替换 + 属性切换」，无渲染逻辑改动，回归面小、可与 94 项冒烟直接对冲；
- CM6 语法高亮、mermaid 出图是**运行时重配置**（JS 换 highlightStyle / `mermaid.initialize` 重渲染），牵动渲染管线，独立成阶段可单独验收；
- P1 落地后 `data-theme` 切换链路已通，P2 只是「让更多区域消费同一令牌」。

### 阶段 2（0.1.43 收尾或 0.1.44）：编辑器/预览/图表深水区

1. CM6 语法高亮：按明暗切换 `HighlightStyle`（浅色沿用默认；暗色用 `@lezer/highlight` 的暗色 style），主题切换时对活动标签 `view.dispatch` 重配。

4. Layer 3 内置主题微调：为 dim/night/dracula 等热门暗色写定向 `--mh-*` 覆盖（2~4 个）。
5. （可选，非必须）自研 `markhunter-classic-dark`、`markhunter-paper` → 皮肤数 37。
