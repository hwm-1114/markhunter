## 0. 现状核对：为什么现在"无法同时打开"

| 用户感受 | 代码事实 | 实测证据 |
|---|---|---|
| 「多个文件不能同时看」 | 整个窗口只有 **1 个 `EditorView` 实例**（`src/renderer/tabs.js:247`），标签切换靠 `view.setState(tab.state)`（`tabs.js:824`）重建视图；所谓"分屏"只有 `编辑器 ↔ 预览`（`preview.js:353-388`），没有编辑器↔编辑器 | 截图 `02-md-split`：左编辑器 + 右预览，无法再放入第二个编辑器 |
| 「单个文件不能开多个会话」 | `openFile` 按路径严格去重，命中即 `switchTab` 返回已有标签（`tabs.js:283-287`）；`tabs` 是扁平数组，一个文件 = 一个标签 = 一段光标/滚动 | 实测：同一文件连续 `openFile` 三次 → 该文件标签数 **= 1** |
| 「无法同时打开（第二个窗口）」 | 第二个窗口打开同一文件会被**强制只读**（`src/main/filewatch.js:151-155` 发 `file-shared-open` → `src/renderer/app.js:1320-1326` 转只读 + toast），解除入口藏在标签右键菜单里 | 冒烟用例 `mwSharedReadOnly` 正是断言这一行为；用户看到的只是 🔒 徽标 |
| 「标签不能拖出去」 | 无任何标签撕裂/窗口间迁移逻辑（全仓无 `moveTabToWindow` 类实现） | — |
| 附带：光标还会丢 | 切换标签时只有滚动位置被记忆，光标位置不记忆（`tabs.js:228-242` 只在 `docChanged` 回写 state） | 实测：切走再切回，光标 145 → 0 |

**结论**：这不是"没做入口"，而是当前数据模型（一个窗口 = 一个视图 = 一组标签）从根上不支持。要做多视图，必须先做**文档层与视图层分离**，否则任何"再开一个编辑器"的补丁都会立刻撞上状态串台。

## 1. 目标与非目标

### 1.1 目标（可验收）

- **G1 同窗口双栏**：可把两个标签左右并排（各自独立标签栏、独立滚动/光标），分隔条可拖拽，比例随会话保存。
- **G2 同一文件多视图**：同一文件可在两个栏（或两个窗口）中各开一个视图，内容实时一致，光标/滚动互不干扰。
- **G3 视图级开关标签**：关闭其中一个视图不落盘、不提示；**最后一个视图**关闭时才走"未保存确认 → 保存/丢弃"。
- **G4 布局持久化**：重启后恢复「哪些栏、每栏哪些文件、活动项、比例、焦点栏」；旧会话格式自动兼容。
- **G5 跨窗口多会话**：第二窗口默认仍为只读观察窗，但提供**一键"抢占编辑"**；抢占后原窗口自动转只读并提示（消除"打不开"的体感）。后续可开关式支持"双可编辑 + 冲突三选一"。
- **G6 键盘可达**：`Ctrl+\` 分屏/取消分屏、`Ctrl+1/2` 聚焦栏、`Ctrl+W` 关当前视图、`Ctrl+Tab` 在当前栏循环、`Ctrl+Shift+T` 重开刚关闭的标签。
- **G7 不回归**：现有 183 项冒烟全绿；新增分屏/多视图用例 ≥ 20 项。
- **G8 顺带兑付体验清单**（§4）中标注 P0/P1 的条目。

### 1.2 非目标（本版不做，避免摊大）

- 不做 CRDT / OT 实时协同编辑（多端实时合并）。
- 不做 >2 栏网格布局、不做上下分屏（**已拍板：0.5.0 只做左右双栏**，3 栏/上下分屏留待反馈）。
- 不做标签拖出为独立窗口 / 窗口间拖动（0.5.1+ 备选，先看双栏使用率）。

- 不重写预览渲染栈、不引入虚拟滚动大改。

## 2. 架构方案

### 2.1 现状结构（改造对象）

```
tabs.js:  tabs[]（标签）  activeTab  view(唯一 EditorView)  saveQueue
          tab = { id, path, name, lang, state, dirty, saveTimer, pinned, kind?, readOnly? }
          kind: undefined(文本) | 'image' | 'diff' | 'chunked' | 'viewer-lg'
          DOM：#tabs / #editor-host / #image-host / #diff-host / #viewer-bar / #preview-host
```

### 2.2 目标结构：文档（Document）/ 面板（Pane）/ 视图（View）三层

```
Document（内容真源，按路径唯一）
  { id, path, name, lang, kind, encoding, eol, crlf, dirty, state: EditorState,
    chunk?, vwin?, saveTimer, lastSavedAt, views: Set<viewId>, closed?: false }

Pane（一个栏）
  { id, el, tabsEl, bodyEl, docs: [docId...], activeDocId, pinned:Set, view: EditorView,
    mode: 'edit'|'preview'|'split'（沿用现有预览模式语义） }

ViewRegistry
  { docs: Map<path, Document>, panes: [Pane], focusPaneId, activeOf(paneId) }
```

- **`Document` 持有 `EditorState`**；`Pane.view` 是独立的 `EditorView`。
- 同一 `Document` 可被多个 `Pane` 引用 → 每个 pane 一个 `EditorView`，各自持有**独立 state**（见 2.3）。
- 图片 / 对比 / 大文件查看器 / 分段模式都归一化为 `Document.kind`，按 pane 渲染（DOM 节点按 pane 生成）。

### 2.3 同文件多视图：内容一致性怎么保证

CM6 的选区/折叠都在 `EditorState` 内，**共享同一个 state 会导致两个视图光标同步**，不满足"两处对照"。因此：

- 每个视图持有**独立 `EditorState`**，通过**变更广播**保持内容一致：
  1. 本地事务 `tr`（`view.dispatch` 结果）→ 若无 `remote` 注解，则提交给 `Document`：`doc.state = tr.state`、`doc.version++`；
  2. 向同文档其它视图广播 `tr.changes`，以 `annotations: [remoteAnnotation]` 派发；接收方**不再回播**（防环）；
  3. 广播按 `Document` 串行队列执行（`Promise` 链），保证 `ChangeSet` 顺序与基线一致；落后视图先用 `ChangeSet.compose` 补齐再追平。
- **不变量（写进代码注释 + 单测）**：任一时刻只有一个视图在产生用户输入；`Document.state` 是所有视图的超集基线；广播失败（视图已销毁）静默跳过。
- 需要新增 `src/renderer/docmodel.js`：`createDocRegistry()`（open/close/applyLocal/applyRemote/broadcast/serialize）。
- **分段模式（chunked）**：`appendChunkText` / `ensureFullyLoaded` 从"每个 tab 一份"上移到 `Document`，追加时对所有视图广播（当前实现只处理活动视图 + 单 state，改造后要注意 `CHUNK_MARKER_RE` 剥离只在保存路径做一次）。
- **查看器（viewer-lg）**：窗口内容天然每个视图不同（不同字节偏移），**不做内容广播**；同文件两个视图各看各的窗口，保存走各自的 `regionStart/byteLen`（需要在 UI 上明确"区域编辑是窗口级操作"）。

### 2.4 语义决定（需要在实现时固定下来）

| 关注点 | 决定 | 理由 |
|---|---|---|
| 内容 | 实时双向同步（同上） | 用户预期"同一文件就是同一份内容" |
| 光标/选区/折叠 | 各视图独立 | 这是"同文件多视图"的核心价值（对照编辑） |
| 滚动 | 独立（可选"链接滚动"开关，P2 后置） | 对照场景常需各自滚动 |
| 撤销/重做 | **每视图独立撤销栈**；remote 变更仍进入本地历史（CM 默认），因此撤销**可能撤掉对方刚输入的内容**——在状态栏/首次分屏时给出一次性提示（"两栏共享同一份内容，撤销按栏独立"） | 避免自研历史合并（高风险）；文档化行为即可 |
| 脏标记 / 保存 | 以 `Document` 为单位（任一视图输入 → 整篇脏；保存写一次盘，所有视图同步） | 与"同一文件同一份内容"一致 |
| 关闭视图 | 关视图不落盘；`Document.views.size === 0` 时才进入关闭流程（脏则确认） | 避免"关一栏把文件写坏"（同 A5 缺陷的教训） |
| 文件被外部修改 | 沿用现有外部修改链路，但要**广播到该文档的全部视图**（现在按 `tabs.find(path)` 只处理第一个） | 现在 `tabs.js:1589` 的 `find` 在多视图下必然漏 |

### 2.5 布局与会话持久化

- 新格式（写入）：
```json
{ "layout": { "orientation": "h", "sizes": [0.5, 0.5], "focus": 0,
  "panes": [ { "docs": ["F:/a.md", "F:/b.txt"], "active": 0, "pinned": [0] },
             { "docs": ["F:/a.md"], "active": 0, "pinned": [] } ] } }
```
- 读入时：有 `layout` 用 `layout`；否则把旧 `{paths, active, pinned}` 映射成单栏（**保证老用户会话不丢**）。
- 恢复顺序：目录 → 逐栏并行打开（沿用 `restoreSession` 的并发池）→ 去重（同文件多视图按"每栏各开一次"）→ 应用比例/焦点 → 最后激活 `active`。上限从 200 标签调整为「总视图数 ≤ 240 且每栏 ≤ 200」。
- 无头恢复（无文件系统权限/文件缺失）继续静默跳过。

### 2.6 跨窗口多会话（G5）

主进程新增锁表，三档语义按顺序落地：

- **L1（现状保留）**：第二窗口只读 + 🔒 徽标。
- **L2（本版做）**：只读观察窗上给一个**显眼的"✏️ 接管编辑"按钮**（顶部横幅，而不是藏在标签右键）；点击后主进程把编辑权移交给本窗口，原窗口收到 `file-lock-changed` 转只读并 toast「X 窗口已接管编辑」。
- **L3（可选，默认关）**：双方都可编辑；保存前主进程比对 `mtime/size`，若与"上次已知"不一致则返回冲突，渲染端弹「保留本窗口 / 载入对方 / 打开对比」三选（复用现有对比标签）。
- 锁表实现：`filewatch.js` 已有 `watchers: path → winId → entry`，直接扩展 `entry.mode = 'edit' | 'read'` 与 `ipcMain.handle('doc:claim-edit')`；窗口 `closed` 时释放（顺带修 B3 的 `fs.unwatchFile` 全量移除问题）。

### 2.7 兼容层（保证 183 项冒烟不被重构摧毁）

| 现有 API | 保留实现 |
|---|---|
| `getActiveTab()` | 返回**焦点 pane** 的活动 Document |
| `openFile(path, opts)` | 默认在焦点 pane 打开；已打开且 `!opts.forceNew` → 激活该 pane 内已有视图（**旧行为不变**） |
| `switchTab/getSession/findTabByPath/closeByPath/closeTab/closeAll/saveNow/applySnippet/jumpToLine/...` | 全部保留签名，内部路由到焦点 pane / 该文档的全部视图 |
| `getView()` | 返回焦点 pane 的 `EditorView`（冒烟大量用例依赖它） |
| `getSession()` | 返回单栏拼接视图（`paths/active/pinned`）＋新增 `layout` 字段 |
| `window.__app.editor` | 追加 `panes/focusPane/splitView/copyToOtherPane` 等新接口 |

- 新建 `src/renderer/docmodel.js`：`Document` 注册表（open/close/rename/relocate/dirty/save 委托），`tabs.js` 的 `tab` 变成 `doc + paneRef` 的兼容壳。
- `tabs.js` 内部：`tabs[]` → `panes[0].docs[]`（**只允许 1 个 pane**），所有 `activeTab` 读写改走 `activeDoc()`；`saveQueue`、filewatch 订阅、会话快照同步迁移。
- DOM 不改（仍是 `#tabs` + `#editor-host`），避免一次动太多。
- **验收**：183 项冒烟全绿（这是本阶段唯一的产出指标）；新增 `docRegistryUnit`（同文件重复 open → 单文档多视图引用计数正确）。

### Phase 2 — 双栏分屏（3～4 天）

- DOM：`#editor-wrap` → `#editor-panes`（`.pane > .pane-tabs + .pane-body`）+ `.pane-divider`；`#image-host/#diff-host/#viewer-bar/#preview-host` 按 pane 生成（模板函数化）。
- 交互：`Ctrl+\` 分屏/合屏；拖动标签到编辑区左/右边缘 → 在该侧开栏；拖动分隔条调比例（复用 `initDragResize`）；`Ctrl+1/2` 聚焦；非焦点栏标签去饱和显示；`onTabSwitch` 只对焦栏触发预览。
- 焦点模型：`focusPaneId` + 点击/快捷键切换；`getActiveTab()` 返回焦栏活动文档。
- **验收**：`splitBasic`（两栏渲染/独立滚动）、`splitIndependentTabs`（两栏各自标签栏）、`splitDragDrop`（拖标签分屏）、`splitResize`（比例 + 最小宽度）、`splitFocusKeys`（Ctrl+1/2/\\）、`splitCloseLast`（关最后一栏回落单栏）、`splitSessionShape`（会话结构）。

### Phase 3 — 同文件多视图 + 布局持久化（3～4 天）

- 变更广播（2.3）：`remoteAnnotation`、串行队列、`ChangeSet.compose` 追平、视图销毁清理。
- `Document.views` 引用计数驱动的关闭语义（G3）；外部修改广播到全部视图；`saveNow` 写一次盘后所有视图 `dirty=false`。
- 「在另一栏打开」「复制到另一栏」入口（标签右键 + `Ctrl+Alt+→`）。
- 布局持久化（2.5）与会话迁移；`stressSessionFull` 扩展到"240 视图 / 双栏"。
- **验收**：`sameFileTwoPanes`（内容同步 + 光标独立）、`sameFileEditSync`（A 栏输入 → B 栏内容更新）、`sameFileUndo`（记录并断言当前语义）、`sameFileCloseOne`（关一栏不落盘、关第二栏才提示）、`multiViewExternalChange`（外部修改两栏都刷新）、`layoutPersist`（比例/焦点/双栏恢复）、`layoutBackCompat`（旧会话格式）。

### Phase 4 — 跨窗口多会话（2～3 天）

- 主进程锁表 + `doc:claim-edit` / `doc:lock-changed` 事件；渲染端只读横幅 + 「接管编辑」按钮。
- L3 冲突三选一（默认关闭，设置项 `allowMultiWindowEdit`）。
- 顺带修 B3（`fs.unwatchFile` 全量移除导致其它窗口轮询兜底失效）。
- **验收**：`mwClaimEdit`（B 接管 → A 转只读 + toast）、`mwClaimBack`、`mwConflictPrompt`（L3 开关打开时）、`mwNoPollBreak`（一个窗口取消监听不影响另一个的兜底）。

### Phase 5 — 体验流畅度批次（可与 Phase 2-4 并行，按 §4 优先级取）

按 §4 的 P0/P1 条目排期，每批 1～2 天，独立成 PR、独立补冒烟。

## 6. 风险与取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| **tabs.js 重构面大** | 保存/监听/会话/预览/AI/分段/查看器/对比全部以 `tab` 为单位（`activeTab` 引用 60+ 处） | Phase 1 纯重构（行为零变化）+ 兼容层保签名 + 每步冒烟全绿 |
| 撤销语义跨视图 | 两栏共享内容、撤销按栏独立，可能"撤掉对方刚打的字" | 保持 CM 默认语义并 UI 说明；不做自研历史合并 |
| 分段/查看器与多视图耦合 | 分段预读是文档级（可广播），查看器窗口是视图级（不可广播） | 明确区分两类文档的广播策略（§2.3） |
| 跨窗口双编辑冲突 | 无 CRDT，last-write-wins 会丢内容 | 默认只做"接管"（L2），L3 冲突三选一作为可选开关 |
| 性能 | 多视图 = 多 EditorView（内存/测量成本 ×N，且各自持有一份 `EditorState`） | 限制 2 栏；隐藏栏的视图不参与装饰/测量（必要时显式 `requestMeasure`）；大文档继续走分段/查看器分层；分屏用例纳入 `stressTabs100` 类压测 |
| 会话体积 | 多栏 + 同文件多次出现 | `layout` 去重存储路径、恢复时复用同一 `Document` |

## 7. 决策记录

### 7.1 已拍板（2026-08-30）

| 决策点 | 结论 | 影响 |
|---|---|---|
| 分屏形态 | **左右双栏**（不做上下、不做拖出成窗） | Phase 2 只实现 `orientation:'h'` 的 2 栏；布局模型仍按数组设计，为将来留口 |
| 执行顺序 | **先 Phase 0 修高危缺陷**；Phase 1-4 已被 0.4.0 大文件线插队，顺延 **0.5.0** | 分屏会成倍放大撤销截断/CRLF/伪只读/删除复活这四类静默数据丢失 |
| 跨窗口同文件 | **只读观察窗 + 显性「✏️ 接管编辑」按钮**（L2） | Phase 4 只做锁表 + 编辑权移交 + 提示；L3 冲突三选一降为 0.5.1 可选开关（默认关） |
| 体验批次 | **精选 11 条**（见 §1.3） | 0.5.0 的体验工作量锁定 ≈ 6 人日，其余顺延 0.5.1 |

### 7.2 实施中仍需就地决定的小问题（不再单独确认，按推荐值执行）

1. 同文件双栏的撤销语义：保留 CM 默认（每栏独立栈，remote 变更进本地历史），首次分屏时给一次性说明提示。
2. 「接管编辑」后原窗口的处置：转只读 + toast，不自动关闭，不弹原生对话框。
3. 双栏上限：硬上限 2 栏（`Ctrl+\` 在已有 2 栏时表示合并）。
4. 分段（chunked）文档在双栏下：内容广播（等同普通文档）；查看器（viewer-lg）不广播（窗口级）。
5. 右键打开目录（`--dir`）采用**拉取式**优先：渲染端 boot 结束前主动 `takeOpenDir()`，主进程同时保留推送；`--dir` 生效时该窗口不恢复上次会话（干净窗口），被顶掉的会话进"最近关闭"。
6. 发布验收必须包含"重装到 `F:\MarkHunter` 后用右键菜单实测"（本机现装的 0.1.46 会掩盖所有新修复；0.4.0 发布验收同样适用，且本次已在 `build/installer.nsh` 补上盘符右键 `Drive\shell\MarkHunter`）。
