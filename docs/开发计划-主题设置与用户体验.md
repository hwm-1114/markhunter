## 0. 先决结论（三处与任务书不同的勘误）

1. **皮肤数量**：daisyUI v5 内置主题为 **32 种**（非 30+ 的模糊说法），加「markhunter-classic」= **33 种**。要达到任务书写的「35+」，需再自研 2 种（方案见 §3.5：`markhunter-classic-dark` + `markhunter-paper`）→ 共 **35 种**。建议 0.1.43 直接按 35 种交付。
2. **默认皮肤取 `markhunter-classic`**（经典皮肤作为 daisyUI 自研主题保留，默认值即经典，老用户观感零变化、冒烟测试零破坏）。
3. **构建链路必须新增 CSS 构建步骤**：esbuild 无法执行 PostCSS 插件（`@tailwindcss/postcss`），需新增 `scripts/build-css.js`（PostCSS 编译 `theme.css` → `dist/theme.css`），`index.html` 增加一个 `<link>`。这是本方案唯一触碰构建脚本的地方。

## 1. 设置键设计

### 1.1 键定义（`src/main/settings.js`）

```js
// ALLOWED_KEYS 追加
'themeName',

// DEFAULTS 追加（默认经典皮肤，零迁移成本）
themeName: 'markhunter-classic', // 主题名：daisyUI 32 内置 + markhunter 自研，白名单校验
```

- `ALLOWED_KEYS` 只控制「键名」白名单；**值校验单独做**（见 1.2），否则任意字符串会原样落盘。
- `toRendererSettings()` 是 `{ ...s }` 展开，`themeName` 自动透传给渲染进程，无需改 `settings:get`。
- 持久化走现有 `persist()`，`settings.json` 新增一行 `"themeName": "markhunter-classic"`，向后兼容（旧文件无此键 → DEFAULTS 兜底）。

### 1.2 取值集合与白名单校验

取值集合 = 35 个主题名（见 §3 分组表）。校验放主进程（S6 风格，防脏值）：

```js
// src/main/settings.js 顶部
const THEME_NAMES = new Set([
  'markhunter-classic', 'light', 'dark', 'cupcake', 'bumblebee', 'emerald',
  'corporate', 'synthwave', 'retro', 'cyberpunk', 'valentine', 'halloween',
  'garden', 'forest', 'aqua', 'lofi', 'pastel', 'fantasy', 'wireframe',
  'black', 'luxury', 'dracula', 'cmyk', 'autumn', 'business', 'acid',
  'lemonade', 'night', 'coffee', 'winter', 'dim', 'nord', 'sunset',
  'markhunter-classic-dark', 'markhunter-paper',
]);
const DARK_THEMES = new Set([/* 12 内置暗色 + 2 自研暗色，见 §3.4，用于主进程 backgroundColor */]);

// registerSettingsIpc 的 settings:set handler 内、sanitizePatch 之后：
if (p.themeName !== undefined) {
  if (typeof p.themeName !== 'string' || !THEME_NAMES.has(p.themeName)) delete p.themeName;
}
```

- 非法值（如 `hacker-mode`）静默丢弃 → 与现有 sanitize 行为一致。
- `THEME_NAMES` / `DARK_THEMES` 建议放主进程新模块 `src/main/themes.js`（main.js 的 backgroundColor 与 settings.js 共用同一份，避免两处漂移）；渲染进程下拉列表用 `src/renderer/themes.js`（含中文名/分组/明暗标记）。两处列表用冒烟用例交叉校验（§6 `themeCatalog`）。

### 1.3 主进程窗口底色（防闪白，配合 §4.2）

`main.js createWindow()`：

```js
const { loadSettings } = require('./settings');
const { DARK_THEMES } = require('./themes');
// ...
```

## 2. 设置面板 UI 方案（openSettings）

### 2.1 字段结构

在 `openSettings()` 的 `body.append(...)` 中**追加**一个「主题」字段（放在「滚动条宽度」之后、AI 配置之前，视觉上属于外观区）：

```js
// 主题字段
const themeField = document.createElement('div');
themeField.className = 'field';
const themeLabel = document.createElement('label');
themeLabel.textContent = '主题皮肤';
const themeSelect = document.createElement('select');
themeSelect.className = 'field-select';            // 新类，样式仿 .ai-model-select 抽取为通用
const prevTheme = s.themeName;                     // 取消时还原
// 按 §3 分组表渲染 <optgroup>：MarkHunter 经典 / 推荐 · 浅色 / 浅色主题 / 深色主题
for (const group of THEME_GROUPS) { /* 生成 optgroup + option */ }
themeSelect.value = s.themeName;
themeSelect.addEventListener('change', () => applyTheme(themeSelect.value)); // 即时预览
themeField.append(themeLabel, themeSelect);
```

- **交互 = 整窗即时预览**：`change` 即调 `applyTheme()`（§4.1），下拉切换的瞬间整个应用（含设置弹窗自身、编辑器、预览、右键菜单）全部换肤，天然就是最真实的「色板预览」，无需额外画 swatch。`option` 文案格式 `"night · 深蓝夜"`（主题名 + 中文说明）。
- **取消还原**：取消按钮 onClick 里加 `applyTheme(prevTheme)`；保存走 §2.2。
- 复用一个新 `.field-select` 样式类（现 `.ai-model-select` 是专用类，抽成通用类，`ai-model-select` 改为同时挂两个类或合并规则，二选一，避免复制粘贴）。

### 2.2 保存逻辑（现有 `保存` onClick 内追加）

```js
const patch = { /* ...现有字段... */, themeName: themeSelect.value };
state.settings = await window.api.setSettings(patch);
// ...现有副作用...
applyTheme(patch.themeName);   // 幂等，与即时预览一致
```

- 保存后 `toast('设置已保存')` 不变；皮肤已实时可见，无需额外提示。
- `settingsAI` 冒烟用例断言 `.ai-model-select` 存在 —— 主题 select 用 `.field-select` 类，不冲突。

## 4. 启动与保存流程（技术集成方案）

### 4.1 渲染进程 `applyTheme`（app.js）

```js
const applyTheme = (name) => {
  const t = typeof name === 'string' && name ? name : 'markhunter-classic';
  document.documentElement.setAttribute('data-theme', t);
  // 让 mermaid 跟随明暗（§4.5）
  if (mermaidThemeFor(t) !== lastMermaidTheme) { lastMermaidTheme = mermaidThemeFor(t); }
  const tab = getActiveTab();
  if (tab && isMarkdown(tab.name) && preview.getMode() !== 'edit') preview.render(); // 重新出图
};
```

- `boot()` 第 2 步（`getSettings` 之后、`applyScrollbarWidth` 旁）调用 `applyTheme(state.settings.themeName)` —— 幂等，preload 已设过则无感。
- `window.__app` 暴露 `applyTheme`（冒烟用）。

### 4.2 防闪白（双层）

1. **主进程**：`backgroundColor` 按明暗给近似色（§1.3）→ 首帧即非白。
2. **preload**（`src/preload/preload.js`，CSP `script-src 'self'` 禁内联脚本，故走 preload）：

```js
const theme = ipcRenderer.sendSync('theme:get-sync'); // 主进程同步返回 loadSettings().themeName
(function setTheme(t) {
  if (document.documentElement) document.documentElement.setAttribute('data-theme', t);
  else setTimeout(() => setTheme(t), 0);   // documentElement 未就绪时下个宏任务重试（仍早于首帧绘制）
})(theme);
```

主进程注册：

```js
ipcMain.on('theme:get-sync', (e) => { e.returnValue = loadSettings().themeName || 'markhunter-classic'; });
```

- 渲染进程任何 JS 运行前，`data-theme` 已就位 → 首帧即目标主题，零闪白。

新增依赖（devDependencies）：`tailwindcss@^4`、`@tailwindcss/postcss@^4`、`daisyui@^5`、`postcss@^8`。

## 5. 暗色跟随（二期，本期不做）

- **本期**：只做手动选择（推荐，符合 0.1.43 范围）。理由：`themeName` 值域保持纯主题名，无「system」伪值，校验/持久化/冒烟都简单。
- **二期方案（预留）**：
  1. `themeName` 增加伪值 `'system'`（或独立布尔键 `followSystemTheme`），主进程 `nativeTheme.on('updated')` 监听系统切换，`webContents.send('theme:system-changed', isDark)`，渲染进程把 system 模式映射到「当前明暗偏好主题」（如 `dim` / `winter`）。
  2. daisyUI 主题自带 `prefersdark: true` 标记 + CSS `@media (prefers-color-scheme)` 可做无 JS 的自动跟随，但跨主题映射（用户选 dark 跟随主题）仍需 JS。
  3. 二期再做「明暗两套分别记忆」（`themeNameLight` / `themeNameDark`）。
- 本期 UI 上不加任何「跟随系统」控件，避免半成品。

| 用例 | 断言内容 | 实现要点 |
|---|---|---|
| `themeDefault` | `getSettings().themeName === 'markhunter-classic'` 且 `document.documentElement.getAttribute('data-theme') === 'markhunter-classic'` | boot/preload 已生效 |
| `themeApplyDirect` | `app.applyTheme('night')` 后 html 属性 = `night`；`getComputedStyle(document.body).color` 与 classic 时不同；`getComputedStyle(document.documentElement).getPropertyValue('--bg')` 非空且变化 | 断言桥接变量真的变了 |
| `themeApplyViaUI`（真实链路） | 点 `#btn-settings` → 找到 `.field-select` 改 value=`winter` → 点保存 → 断言 html 属性=winter、`getSettings().themeName==='winter'` | 覆盖 openSettings 保存分支；顺带验证 modal 内 select 渲染（`settingsUI` 的 `inputs>=5` 不受影响，select 不计入） |
| `themePersist` | `api.setSettings({themeName:'dim'})` 后，主进程直接读 `app.getPath('userData')/settings.json` 断言含 `"themeName": "dim"` | 真持久化断言（单进程冒烟无法真重启，落盘即证）；随后还原 |
| `themeWhitelist` | `api.setSettings({themeName:'hacker-mode'})` → `getSettings().themeName` 不变（仍为当前值） | 主进程值校验 |
| `themeCatalog` | 对渲染进程 `THEMES` 全部 35 个 id 逐一 `setSettings` + `getSettings` 回读相等 | 交叉校验渲染/主进程主题清单不漂移（35 次 IPC 很快） |
| `themeRestore` | 末尾还原 classic，断言 html 属性与 `--bg` 变量回位 | 防串扰 |

### 6.1 现有 94 项用例影响分析（只读核对结论）

- **零颜色断言**：grep 确认 smoke.js 无任何 `rgb(...)`/hex 断言；`getComputedStyle` 只用于 `userSelect`（属性值，与主题无关）与 `--scrollbar-width`（变量，不受影响）。
- **可能受影响的用例**：
  - `settingsUI`：数 `#modal-body input` ≥ 5 —— 主题字段是 `<select>`，不计数，**不受影响**；hint 文案断言（'2048'/'40'）不受影响。
  - `settingsAI`：断言 `.ai-model-select` 存在 —— 主题 select 用 `.field-select`，**不冲突**。
  - `userSelect` / `scrollbarSetting` / `caretVisible` / `zoomPreview`：均与颜色无关，**不受影响**。
- **前提红线**：styles.css 重构后**经典皮肤计算色值必须与现状逐像素一致**（含 `.cm-editor` 背景 `#ffffff`、`.modal` 白底等），否则任何「凭截图对比」的隐性回归都无从发现 —— 冒烟只能保证不炸，视觉一致性靠 §7 的人工清单。
- **新用例回归**：`indentSizeApply` 等走 modal 保存路径的用例，其 patch 现在会多带 `themeName`（select 默认值）—— 主进程白名单放行，无副作用。
