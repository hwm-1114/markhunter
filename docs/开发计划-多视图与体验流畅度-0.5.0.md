### 1.2 非目标

- 不做 CRDT / OT 实时协同编辑。
- 不做 >2 栏网格、不做上下分屏（**已拍板：只做左右双栏**）。
- 不做标签拖出为独立窗口（0.5.1+ 备选）。
- 不做跨窗口「双可编辑 + 冲突合并」（L3 冲突三选一降为 0.5.1 可选开关，默认关）。
- 不重写预览渲染栈。

**开工动作（Phase 1 第 0 步，强制）**：

1. 重读 `src/renderer/tabs.js` 全文（2040 行），把 `activeTab` 的 83 处按「读/写/路由」分类成清单 —— **该清单已产出：`docs/开发计划-多视图-Phase1-重构清单.md`（A–O 15 类，含全量行号）**，直接用它，不要重做。
2. 把 `kind` 枚举补全为 **`undefined`（普通文本）| `'image'` | `'diff'` | `'chunked'` | `'viewer-lg'` | `'huge'`**，并明确三类文档的**窗口级 vs 文档级**语义：

   | 类别 | kind | 内容是否跨视图广播 | 理由 |
   |---|---|---|---|
   | 文档级 | `undefined`、`'chunked'`、`'image'` | **广播** | 同一文件同一份内容 |
   | 窗口级 | `'viewer-lg'` | **不广播**（各视图各看各的字节窗口） | 窗口内容天然不同（0.3.0 §2.3） |
   | 窗口级（新） | **`'huge'`** | **不广播**（视口行由各自滚动决定）；但 overlay 编辑一旦接入，**脏状态与保存必须是文档级** | 同一个 overlay doc（路径单例）被多视图引用 |

3. `getView()` 必须继续返回**焦点 pane** 的 `EditorView`（冒烟大量用例依赖它）；焦点 pane 是 huge 时 CM 为空文档 —— 这一条已有行为要保持，**不要**在 Phase 1 顺手改 `find.js`（见 §6 待决项）。

**为什么不会再打断别的窗口**：Node 的 `fs.watchFile(path, opts, listener)` 允许同一路径挂多个监听器，而 `fs.unwatchFile(path)`（不带 listener）会移除该路径**全部**监听器（本机 node 24 实测：两个监听器 A/B 都失效）。修复前 `entry.poller` 已置 `true` → `fallbackToPoll` 的 `if (entry.poller) return` 使得被打断的窗口**永不重建**兜底，此后外部修改静默丢失。带 listener 摘除后，其它窗口的 StatWatcher 与回调原样存活。

**验证**（`mwNoPollBreak`，主进程 + 渲染端双面事实）：
- 强制降级手段：对**不存在的路径**调 `fs:watch-file` —— `fs.watch` 同步抛 `ENOENT`（node 实测）→ `catch { fallbackToPoll }`，这是唯一能确定性复现"轮询兜底"的入口（真实文件在 Windows 上 `fs.watch` 恒成功）；
- `__debugWatchers(path)`（`filewatch.js:400`，冒烟探针专用，不暴露给渲染进程）给出 watcher 实况；
- 探针实测输出（`--exttest`）：`w0=[{winId:1,poller:true,hasPollFn:true,fsw:false},{winId:2,...}]` → win1 取消监听后 `w1=[{winId:2,poller:true,hasPollFn:true}]` → 主进程 `fs.writeFileSync` 真·外部写 → win2 的 `file-changed` 探针 `hits2=1`、win1 `hits1=0`。

## 10.2 逐条实现要点（含"多视图一致性"怎么保证）

**A1 快速打开**：数据源 = `search-worker` 的 `walk()`（与全局搜索**同一套** `SKIP_DIRS`/隐藏项口径 ⇒ "清单里有 = 搜得到"，不会长出第二套目录规则）。
- **不卡顿**靠三件事：① **流式**——worker 每 200 个文件回一批（事件 `search:files-progress`），渲染端收到即增量匹配（按下 Ctrl+P 时首批通常已在路上）；② **缓存**——worker 侧 `Map<dir, files[]>` LRU 8 个目录，第二次呼出毫秒级命中（`search:files` 的返回值带 `cached` 标志，用例直接断言它）；③ **渲染上限**——结果只渲染前 200 行。
- **安全面**：只读**目录清单**（文件名），不新增任何读文件内容的通道；主进程侧清单任务与搜索任务**并行独立记账**，因此"搜索跑着的时候按 Ctrl+P"照样可用。
- **多视图**：快速打开是窗口级单例（打开一个文件 = 进**焦点栏**），复用 `editor.openFile`，不引入新的栏语义。

**A3 标签栏溢出（按 pane 是硬要求）**：
- 判据 = **该栏自己的** `.tabs` 的 `scrollWidth/clientWidth`（`tabsOverflowing(pane)`）；两栏各有一个 `▾` 按钮与一份菜单，数据源是 `registry.docsOf(pane.id)` / `activeOf(pane.id)`，**没有任何全窗口唯一活动标签的假设**。
- 三个入口：① 滚轮（竖向 `deltaY` 换算横向滚动，只在真的溢出时 `preventDefault`，未溢出时把事件让回页面）；② `▾` 下拉（只列本栏标签，点击 = 聚焦本栏 + 切换）；③ `Ctrl+Tab` 浮层（窗口级单例 DOM，但内容恒取**焦点栏** —— 双栏下不会串栏）。
- 溢出判据的重算点：`renderPaneTabs` 末尾、`layoutPanes`（分栏/合栏/拖分隔条）末尾、`window.resize`、以及 `ResizeObserver(panesRoot)`（覆盖面板折叠/最大化、侧栏拖宽等一切改栏宽的路径）。
- `#tabs` / `.pane-tabs` / `.tab` 的既有 DOM 结构与 ID **一字未改**（`splitIndependentTabs` 断言的 `tabsIdP0 === 'tabs'` 不受影响）；`▾` 按钮与菜单挂在 `.pane`（`position:relative`）上，因此不会被标签栏的横向滚动卷走，也不参与标签栏重建。

**B1 大纲**：数据源 = **焦点栏的活动文档**（`outline.js` 顶部注释的三条硬口径）。三条类型门控写成**与 UI 同源的纯函数** `outlineSupported(name, kind)`：非 Markdown / `huge` / `viewer-lg` / `image` / `diff` 一律不显示（chunked 显示，但标题标注"仅已加载部分"，不假装完整）。
- 解析缓存键 = `(tab, tab.state)`：CM 的 `EditorState` 不可变 ⇒ 引用恒等即内容未变 ⇒ 光标移动路径零解析成本。
- 随光标高亮：`tabs.js` 的 CM `updateListener` 新增统一出口 `onCursorMove(tab, line, docChanged)`，归属判定沿用 Phase 2 的 `registry.docOfView(u.view)`（**由派发事务的视图反查文档**），回调里只认"焦点栏的文档"，旁路异常被 try/catch 隔离，绝不影响编辑主链路。

**B8 字号/行高**：落地方式 = **根元素 CSS 变量**（`--mh-editor-font-size` / `--mh-editor-line-height` / `--mh-preview-font-size`）⇒ 所有栏的 CM 与预览实例**天然同时生效**（多视图一致性最省事的正确解，不需要逐视图派发）。字号变化后调 `editor.refreshMeasure()`（逐栏 `requestMeasure`），否则 CM 的字符宽度缓存/滚动高度滞后。
- `Ctrl+0` 语义**一并定义**为「**视图缩放复位**」：编辑器字号/行高/预览字号回默认 **且** 预览缩放回 100%（后者是 Ctrl+0 的原有行为，`zoomPreview` 断言的 `#preview-host.style.zoom === '1'` 保持）。
- 步进时**当前值从主进程现读**（`getSettings()`）而不是用 `state.settings` 缓存：settings.json 是唯一真值，缓存陈旧会让"+1 跳两格"。

**E1 底部面板**：默认折叠（启动即加 `.collapsed`），`switchPanel()`（Ctrl+F / Ctrl+H / ▶ 运行 / 全局搜索跳转）按需展开；标题栏新增 `⛶` 最大化/还原（折叠态下点它 = 先展开再最大化，一次点击就有可见效果）；`✕` 与 `Esc` 收起（折叠同时退出最大化）。
**E2 侧栏分区**：三分区折叠态**唯一来源** = `settings.sidebarCollapsed`（键已进 `settings.js` 白名单）；只加/去容器上的 `.collapsed` 类，**树内部一行未改**（`src/renderer/tree.js` 本次**零改动**）。
**F1 帮助面板**：`help.js` 的 `SHORTCUTS` 同时是**面板显示**与**键位分派**的数据源（`app.js` 只提供 `id → 动作`），因此"面板显示的键位"与"真正生效的键位"在结构上不可能漂移。

## 10.6 诚实清单

**弱验证项（如实登记）**：
1. `bottomPanelCollapse` 的"**启动默认折叠**"用 `__app.bottomPanel.getState().bootCollapsed` 断言 —— 它是 **boot 当下对真实 DOM 的现场快照**（`setPanelCollapsed(true)` 之后立刻读 class），因为在末尾跑的用例无法重放"刚启动"那一刻（前面若干用例已经改过面板状态）。这是对真实 DOM 的观测，不是常量回读，但**不是**"重开一次窗口再看"的端到端复现。
2. `outlinePanel` 的"huge / viewer-lg 不显示大纲"用**与 UI 同源的纯函数** `outline.supports(name, kind)` 断言（不真开一个 >256MB 文件：那会把用例从毫秒级拖到秒级）。真实 DOM 侧的隐藏只覆盖了"非 markdown"（真开 txt）。
3. `fontSizeSetting` 的 `real-key-not-eaten-by-menu` 用 `webContents.sendInputEvent`（走浏览器进程输入管线、会经过菜单快捷键）触发 Ctrl+Plus，判据是"**菜单是否真的把界面缩放了**"（`zoomLevel` 变化）—— 若窗口未获焦点，`sendInputEvent` 空转则两者都不变，**不冤判**。这是对"Electron 默认菜单是否截胡 Ctrl+=/Ctrl+-"这一未知项的**唯一可自动化观测**；真·人手按键仍建议在手工验收里确认一次。
4. `.tabs` 的 `padding-right: 30px` 是为 `▾` 按钮**恒定预留**的（不给滚动内容留白，滚到末尾时最后一个标签的 ✕ 会被按钮压住）。它让"标签栏何时开始溢出"的阈值后移约 22px —— 用例用 14 个长名标签留足余量。
5. `Ctrl+Tab` 浮层用**合成 KeyboardEvent** 驱动（与既有 `splitFocusKeys`/`zoomPreview` 同一口径），不是真实 OS 级按键。

**主动放弃项**：A2（重开关闭标签）、F2（右键常用项）、G1（查找三开关）、G2（查找上限+防抖）本批不做；`find.js` **零改动**。E4 面板宽度持久化、F3 toast 队列等仍按计划顺延 0.5.1+。

**改了既有行为的地方（逐条 + 理由）**：
1. **启动布局**：底部面板默认**折叠**（原为展开 240px 高）。这是 E1 的目标本身；已在 §10.4 逐条核对既有用例。
2. **`Ctrl+Shift+O` 语义变更**：原为"选择目录"（`open-dir` 不判 shift，历史行为），现为"折叠/展开大纲"。`Ctrl+O` 本身**未变**。理由：需要一个大纲键位，且 `Ctrl+Shift+O` 在旧版属"顺带命中"而非文档化键位（README 的快捷键表里没有它）。
3. **Esc 的收起语义**：原直接 `classList.add('collapsed')`，现走 `setPanelCollapsed(true)`（**同时退出最大化**）。可见差异仅发生在"最大化状态下按 Esc"—— 现在是收起到 34px，原来是收起到 34px 但保留 `.maximized`（下次展开会直接 72vh，属原实现的隐性 bug）。
4. **`.tabs` 右内边距 8px → 30px**（为 `▾` 按钮预留，见弱验证项 4）。
5. **键位分派从 if/else 链改为表驱动**（`help.js` 的 `SHORTCUTS` + `app.js` 的 `SHORTCUT_ACTIONS`）：判定结果经 96 组差分探针确认与旧链一致（除有意新增/改绑）。两处细节差异：① 旧链的 `e.key.toLowerCase()` 在 `key` 缺失的合成事件上会抛异常，新表用 `String(e.key)` 容错；② 旧链只在 Esc 分支调 `tree.hideCtx()`，新表把该调用放回 `panel-collapse` 动作里，**行为一致**。
6. **`Ctrl+0` 语义扩展**：由"仅重置预览缩放"变为"视图缩放复位（字号/行高/预览字号 + 预览缩放）"。原行为是其子集，`zoomPreview` 断言不变。
7. **新增设置键 4 个**（`editorFontSize`/`editorLineHeight`/`previewFontSize`/`sidebarCollapsed`）进 `settings.js` 白名单 + 默认值；老 profile 无这些键 → 走默认值，**观感零变化**（13.5px / 1.65 / 14.5px 与改造前硬编码值逐字相同）。
8. **新增 IPC 3 条**（`search:files` / `search:files-cancel` / 事件 `search:files-progress`）—— preload 两端已同步；均为**只读清单**，不新增任意读通道。
9. `app.js` 的 `file-shared-open`/会话/多栏逻辑**未改**；`tabs.js` 的 `getView()`/`findTabByPath()`/`getSession()` 等既有签名与语义**未改**。

**根因（产品缺陷，不是用例）**：`app.js` 的 `clampFont` 原来按 **1 位小数**归整 —— `Math.round(1.65 * 10) / 10` = `Math.round(16.5) / 10` = **1.7**。于是：

| 位置 | 值 |
|---|---|
| `settings.json`（`ctrl-0-persisted=true` 读的就是它） | **1.65**（白名单原样存） |
| 根元素 CSS 变量（`applyFonts` 写进去的） | **1.7**（被夹取函数改掉了） |

即 **settings 与界面静默漂移**：任何走 `applyFonts` 的路径（启动 / 设置弹窗保存 / Ctrl+=、Ctrl+- / Ctrl+0 / 跨窗口设置同步）都会把 `1.65` 显示成 `1.7`；同理 `1.05 → 1.1`。这**不是**"乐观应用没生效"——`applyFonts` 确实排在第一个 `await` 之前、同 tick 生效，**只是它写进去的就是个错值**（首轮我误判为"同 tick 读取"问题，是因为当时 detail 里没有 `fontBefore` 与三个变量的对照；父 agent 提示的"比对口径"方向是对的）。

**修法**：
1. `src/renderer/app.js:47-56` 的 `clampFont` 改为按 **2 位小数**归整（`Math.round(n * 100) / 100`）——行高是倍数域且默认值/设置项步长（0.05）都是两位小数，2 位是它的自然精度；字号域（步长 0.5）不受影响。
2. `src/renderer/app.js:419` 的步进同样改用 2 位小数（`13.75 + 1 = 14.75` 不再被抹掉）。
3. **补一条针对性回归守卫**（本轮新增合取项）：设置弹窗把行高设成 `1.65` → 断言 `settings === 1.65` **且** CSS 变量 `=== '1.65'`（`fractional-line-height-preserved`）。
4. 该用例的 detail 现在并排打印 **want/got**：`ctrl0-want=13.5px/1.65/14.5px got=…(before=…)` —— 同类"落盘与 DOM 不一致"的问题下一轮一眼可见。

**修法自检**（纯 node 复算 `clampFont` 逐值对照）：`1.65 old=1.7 → new=1.65`、`1.05 old=1.1 → new=1.05`；`13.5 / 14.5 / 18 / 2 / 20 / 19 / 32 / 10 / 2.6 / 1` 新旧**逐位相同**（无副作用）；`Ctrl+0` 应用后的期望值 `{"f":"13.5px","l":"1.65","p":"14.5px"}` 与断言 **MATCH**。另：`npm run build` = `0.96 / 3.29 / 4.25 MB`；`node --check`（含 3 个新文件）全通过；内嵌体专项 `ok:true / leftovers:0`；本段 95 处内嵌实参 `failures=0`；用例数仍为 **7**（计数口径 **219 不变**）。

**落栏语义（确定语义，用例逐条断言）**：

**未保存内容的四条路径（硬要求：不许只恢复路径就宣称"内容还在"）**：

| 关闭对象 | 关闭时是否写盘 | 重开时怎么处理 | 用例判据 |

| 普通文本（脏） | 是（`saveNow`） | 落盘成功 ⇒ 读盘即等价恢复；**失败** ⇒ 把手里的文本快照**写回**重开文档并重新标脏（内容不丢） | `unsaved-dirty-snapshot` / `unsaved-save-failed`（**主进程真读磁盘**：`disk === 原始内容` 且不含只存在于编辑后的标记）/ `unsaved-content-restored` |

| 任何（`save:false`） | 否（显式丢弃） | 同"保存失败"分支 | （与上同源） |

**huge 为什么是"降级"而不是"恢复"（真窗口探针实测，两件事各自确证）**：
1. **关闭这条路径从不写源文件**：`closeTab` 里 `saveNow(tab)` = `saveQueue.then(() => doSaveNow(tab))`，`doSaveNow` 要到**微任务**才执行，
   而同一段同步代码紧接着就 `tab.huge = null` + `hv.destroy()` → `doSaveNow` 的 huge 分支命中 `const hv = t.huge; if (!hv) return true;`
   —— **没写盘却返回 true**。探针实测：21.5MB 夹具关闭前后 `size` 完全一致（21556000 → 21556000），文件首 512 字节里没有插入标记（`diskTopHasMark=false`）。
   这是 0.4.0 的既定语义（"这条路径从不写源文件"），不是本批引入的。
2. **恢复区的分片无法重挂**：`huge:doc-close(discard:false)` 把 overlay 块表留在 `<userData>/overlay`，
   但 `huge:doc-open` **恒从磁盘重建块表**（`overlay-ipc.js:309-404`，同 realpath 只在句柄仍存在时复用），
   0.5.0 没有"把恢复区里的分片重挂到新句柄"的入口 ⇒ 只能显式降级。
   探针证据：`hugeDocRecoverList` 返回 `{file:…p6b-huge-21mb.txt, dirtyBlocks:100, sourceExists:true}` —— **内容没丢，只是没能随标签回来**。
3. 因此 `trackClosedSave` 对 `kind==='huge'` **不采信那个假 true**：当时只能硬编码 `savedOnClose=false` 兜住，避免把"静默丢内容"当成恢复成功。
   > **⚠️ 2026-09-13 已过时（t2/t6 收口）**：`doSaveNow` 的 `!hv` 分支现在返回 **`false`**（`tabs.js:3067`；约定见 `:3071`「本次没有发生写盘，不等于写失败」），`trackClosedSave` 对 huge 与普通标签走**同一条"按返回值推导 `savedOnClose`"**的路径（`tabs.js:2208`），硬编码分支已删除。**行为结论不变**（huge 关标签仍不写源文件、重开仍显式降级），只是不再"先撒一个 true 再兜住"。用例 `huge-close-does-not-write-disk` 同时是**回归守卫**：将来若有人把 closeTab 的 huge 路径改成"真的先保存再关"，它会立刻变红并提示把降级断言改成"内容已随磁盘恢复"。

**滚动位置（A2 第 6 条补齐，产品侧新增）**：huge 的滚动位置是**视口首行**，不是像素 `tab.scrollTop`。
关闭时用 `hugeTopLine(tab)` 采集（与 `setHugeVisible` 同一个估算器），重开时交给
`restoreHugeTopLine`（`tabs.js:2169-2195`）：**先轮询等 `getState().indexed` 就绪**（上限 12s，口径同 `app.js` 的 `waitHugeReady`，不硬等固定 sleep），
再 `gotoLine(target)` 复位（`hugeview.scrollToLine` 会把行号 clamp 到"当前已知总行数"，索引未就绪时是估算值，必须先等）。

## 11.8 诚实清单

**弱验证项（如实登记）**：
1. **真正的灾难性回溯无法自动测**：单次 `exec` 是不可中断的（在自动用例里跑它等于挂死渲染进程）。因此"预算到点即中止"这条分支是用**大文档 + 1ms 预算**确定性触发的，而不是"用真·指数级模式撞墙"；静态拒绝那一层只覆盖嵌套量词这一种形状（`(a|a)*` 这类"量化交替"不在静态判据内，只受预算兜底）。
2. **「在终端打开」的真正 spawn 路径没有自动化**：冒烟只跑 `dryRun`（断言白名单、`cwd` 唯一传递通道、`argv=[]`、`shell:false`），**不会真的弹出控制台窗口**。真·spawn 与「用默认程序打开」的真实效果属于手工验收项（`shell:open-path` 的**拒绝**路径有自动断言）。
3. **huge 的"未保存内容恢复"只到"显式降级 + 恢复区有分片"这一层**：0.5.0 没有重挂入口，因此用例断言的是"没丢（恢复区有 dirtyBlocks）+ 明确告诉用户没恢复"，**不是**"内容回到了文档里"。
4. **关闭脏 huge 标签不写盘**这条（#7）是用 21.5MB 单夹具 + 字节数/首 512 字节比对验证的，没有覆盖"closeTab 被其它路径调用"的全部组合（例如 `closeByPath(save:false)`）。
5. **滚动位置断言用"视口首行 > 1000"作判据**（`gotoLine(15000)` → `renderedFrom=14964`），不是像素级相等：huge 的滚动是虚拟滚动 + 索引换算，跨会话像素不可比；行号口径与 `setHugeVisible` 的既有恢复保持一致。

**主动放弃项**：huge 区间查找（只做显式提示，0.5.0 计划 §6 待决项 1 的倾向）；正则分组引用替换（仍是原样插入）；外部文件区的右键菜单未加这五项（`showExternalFileCtx` 有意保持最小集）——树内行与标签均已覆盖。
**已知产品遗留（0.5.1 建议）**：`closeTab` 的 huge 分支"先保存"实际不生效（#7 根因）；正确的修法是让 `hv.save()` 在 `destroy()` 之前完成（或给 `doSaveNow` 传视图实例），本批**未做**（改动面在 0.4.0 的关闭时序上，收益是"关标签即落盘"，与 A2 的降级口径不冲突）。

**改了既有行为的地方（逐条 + 理由）**：
1. **新增键位 `Ctrl+Shift+T`**（`help.js:60` + `app.js:1467`）：F1 面板与分派同源，`helpPanel` 的 `single-source` 自动覆盖；差分探针确认没有吃掉任何既有键位。
2. **`find.js` 的匹配/高亮改用 RegExp `exec`**：修掉变长小写映射的错位（审计低级别清单第 3 条）；默认口径的匹配结果不变（`findAll`/`findDomReuse`/`findReplace` 的期望全部保持一致）。
3. **`find.js` 输入路径加 80ms 防抖**：既有用例在派发 `input` 后等 150–200ms，仍能读到结果（`findAll` 200ms / `findDomReuse` 150ms）；`setQuery` 与替换路径**同步**执行，不受影响。
4. **展示上限 500**：`#find-count` 文本改为「N 处匹配」或「匹配过多：仅显示前 500 处（已截断）」；结果行数 = 展示匹配数（既有用例的 3/50 行断言不受影响，截断提示行用 `.find-more`，不占 `.find-result` 计数）。
5. **`runSearch` 的分支顺序**（#6）：无文档视图的提示提前 —— 只影响 huge/viewer-lg/image/diff 四类（正常文本标签路径逐位不变）。
6. **`closeTab` 新增"入最近关闭栈"**（`tabs.js:2353`）：纯新增副作用（数组 push，上限 20）；`save:false` 路径、视图级关闭路径、`closeAll` 的落盘语义**未改**。
7. **`clipboard:write-text` 收窄为"主进程自拼正文"**：渲染端 `copyText({path,kind})`（不再传 text）——接口形状变了，两端已同步（`preload.js:69`）。
