# MarkHunter 上限实测报告（v0.1.49，2026-08-24）

> 环境：Windows 11 x64 / Electron 43.3.0 / 开发模式真实窗口冒烟（scripts/smoke.js）
> 数据来源：全量冒烟 144 项中 stress 系列用例的实测输出（三轮运行取代表值）

## 一、能打开多少个文件（标签数上限）

| 指标 | 实测值 | 结论 |
|---|---|---|
| 创建 100 个 20KB 文件 | 51ms | — |
| **顺序打开 100 个标签** | **306 ~ 608ms** | 平均 3~6ms/个，无感 |
| 100 标签下的**键入延迟** | **0.1 ~ 0.2ms/键** | O1 徽标增量化后与单标签无差异 |
| 100 标签时渲染进程堆内存 | 43 ~ 78MB | 与空载（~40MB）几乎持平（标签 EditorState 惰性持有） |
| 120 标签会话恢复（重启还原） | 233 ~ 505ms | 并发 6 限流 |
| 会话持久化上限（配置值） | 200 标签 | O2 由 50 提升 |

**结论**：**硬上限：无**（代码不再逐键重建标签 DOM，主瓶颈已消除）。**软上限**：本轮压测到 120 标签所有指标均无劣化拐点；会话配置上限 200，超过 200 个标签重启后仅恢复前 200。建议日常使用 ≤200。

## 二、大文件上限（分层口径）

| 文件大小 | 模式 | 实测 |
|---|---|---|
| ≤ 4MB | 全量加载编辑 | 既有行为不变 |
| 4MB ~ 64MB | chunked 分段可编辑（保存全量补读） | 60MB ×2 同开：打开/切换/滚动预读正常，堆内存 78MB 无异常增长 |
| 64MB ~ 256MB | chunked 可编辑 + **保存走分块流式写**（>64M 字符） | 65MB 多行编辑→保存 1.9~2.0s，内容/大小校验一致 |
| **256MB ~ 4GB** | **只读滑窗查看器**（8MB/窗，⏪⏩ 翻页 / 百分比·字节偏移跳转 / 区域编辑≤40MB 拼接写回） | 3.9GB 稀疏文件：打开即用（首窗 8MB）、翻页/跳转正常；280MB 区域编辑写回校验通过 |
| > 4096MB | 拒绝打开（TOO_LARGE 提示） | 4.1GB 正确拒绝 |

- 查看器对**二进制/控制字符**窗口（如稀疏零字节）：控制字符替换为 `·` 显示并禁止区域编辑（写回会失真）；查看器强制不换行（超长单行在换行模式下 CM 视口测量复杂度失控，实测曾致渲染进程内存失控——已修复）。
- 全局搜索：>10MB 文本文件由「整档跳过」升级为**流式扫描**（≤4GB，行号全局精确）；15MB 文件命中实测行号正确。

## 三、关键路径性能（附）

| 操作 | 实测 |
|---|---|
| 标签切换（滚动位置记忆恢复） | 多帧校正 ~100ms 内稳定 |
| 65MB 保存（流式，7×16M 块） | ~2.0s |
| 280MB 区域编辑写回（拼接流拷贝） | ~1-3s（SSD） |
| 3.9GB 打开至可交互 | <1s（仅读 8MB 窗口） |

## 四、遗留说明

1. 查看器窗口边界截断多字节字符时显示为替换符（各窗口独立解码，查看语义可接受）。
2. viewer-lg 标签不参与外部修改自动重载（窗口模型下偏移漂移无意义）；关闭重开取最新内容。
3. GBK 大文件的流式搜索按 UTF-8 匹配（乱码内容可能漏配），小文件路径行为不变。
