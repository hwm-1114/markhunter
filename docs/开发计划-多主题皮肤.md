## 1. 总览

### 1.1 目标

- **主题引擎**：以 Tailwind CSS v4（CSS-first）+ daisyUI 5 作为「主题引擎」，为 MarkHunter 提供 **35+ 种皮肤**。
- **皮肤构成（实证）**：daisyUI 5.7.18 内置 **35 种主题**（`package/theme/*.css` 实数为 35 个文件）+ 自研「经典」皮肤 `markhunter-classic` = **共 36 种皮肤**，满足并超出「35+」目标；**无需再自研凑数**（调研2 报 34、调研3 报 32 均为误计，见 §5 勘误）。
- **经典皮肤保留**：经典皮肤以 daisyUI 自研主题语法（`@plugin "daisyui/theme"`）保留，`default: true` 作为应用默认，老用户观感零变化、94 项冒烟零破坏。
- **皮肤切换机制**：`<html data-theme="xxx">` + daisyUI 主题令牌，**纯 CSS 属性切换**（实证：每个主题编译为 `:root:has(input.theme-controller[value=X]:checked), [data-theme="X"] { … }`），零运行时 JS、无内联样式注入。
- **设置面板「主题」下拉**：新增「主题」设置项，选项按「经典 / 推荐 / 浅色 / 深色」四组分组；**切换即整窗即时预览**，取消时还原（天然就是最真实的色板预览，无需额外色板面板）。
- **版本节奏**：0.1.43 完成全量接入、冒烟回归与打包发布。

### 1.2 复杂度评级：**M（中等）**

| 维度 | 判断 | 依据 |
|---|---|---|
| 运行时复杂度 | **低** | 主题引擎是纯编译期 CSS；切换 = 属性切换触发 `[data-theme]` 选择器，无 JS 运行时、无 IPC、无新 Node 能力 |
| 构建链路复杂度 | 低~中 | esbuild 步骤原样，前置新增一个 `@tailwindcss/cli` 同步步骤（失败即 exit 1）；发布链 `release.ps1` 零改动自动携带 |
| 改造面 | 中 | 6 个构建/入口文件 + styles.css 约 60 处硬编码色变量化 + JS 侧约 10 处硬编码 + 设置面板/白名单 |
| 回归风险 | 中 | 唯一硬冲突（`--border` 同名）有明确解法；Preflight 必改项仅 2 行；现有 94 项冒烟**零颜色断言**、正确实现下 0 项必然失败 |
| 不触及面 | — | 主进程安全模型 S1-S12、IPC、CSP、electron-builder 配置、release.yml 均零改动 |

结论：**M（中等）**。既不涉及架构级改动（无 Vite、无运行时 JS 引擎），也不是改两行就完事（变量化重构 + 明暗适配是实打实的工作量）。

### 1.4 与现有架构的兼容结论

| 维度 | 结论 | 证据 |
|---|---|---|
| bundle.js（9.3MB） | **零影响** | daisyUI 纯编译期 CSS；不 `import` 任何 daisyUI JS；esbuild 步骤、产物、体积原封不动（调研1 §2.1） |
| styles.css（30KB 手写） | **零重写，视觉理论零回归** | styles.css 无 `@layer`（unlayered），未分层作者样式按规范压过所有 `@layer` 内规则；唯一必改 2 行（`.markdown-body ul/ol` 的 list-style，见 §3.1.5） |
| CSP | **无需改动** | `style-src 'self' 'unsafe-inline'` 原样足够；daisyUI 无内联 `<style>` 注入、无 data: URI 越界（`--fx-noise` 属 `img-src`，CSP 已含 `data:`）；`sandbox/contextIsolation` 与 CSS 无关（调研1 §4） |
| 设置系统 | 新键 `theme` 进 **DEFAULTS + ALLOWED_KEYS 双白名单** | 实证 `settings.js:6`（ALLOWED_KEYS）、`:24`（DEFAULTS）、`:112/116`（sanitizePatch 过滤）；缺一即被静默丢弃 |
| 打包链 | **零改动** | 产物放 `src/renderer/dist/tailwind.css`（`dist/` 已被 .gitignore 覆盖）；`release.ps1` 第 2 步 `node scripts/build.js` 的 `$LASTEXITCODE` 自动拦截失败；electron-builder `files: src/**/*` 已覆盖 |
| 安全加固 S1-S12 | 零影响 | 无新 IPC、无新 Node 能力、无新远程资源请求（调研1 §4） |
| **唯一硬冲突** | **`--border` 同名（必改）** | 实证：daisyUI 每个主题块都有 `--border: 1px`（cupcake/pastel/silk/caramellatte 为 `2px`）——存**边框宽度**；MarkHunter `styles.css:10` `--border: #e3e8ef`——存**边框颜色**；`:root` 与 `[data-theme]` 同特异性、后加载者胜，daisyUI 胜出则全站 `border:1px solid var(--border)` 解析为无效值、**边框全丢**。处置：MarkHunter 侧改名 `--mh-border`（推荐全量 `--mh-*` 前缀，见 §4-Q7） |

**目标**：tailwind.css 产物随构建产出并被 index.html 加载；主题总数实测核实；确认层叠无破坏。

**改动文件（4 个 + 可选 1 个）**

| 文件 | 动作 | 要点 |
|---|---|---|
| `package.json` | 改 | devDependencies 新增：`tailwindcss@^4.3.3`、`@tailwindcss/cli@^4.3.3`、`daisyui@^5.7.18`（三者 npm 实测可装；daisyui 无 peerDependencies）；可选加 `scripts.build:css` / `scripts.dev:css` |
| `src/renderer/tailwind-input.css` | 新增（入库） | Tailwind + daisyUI 入口，见下方代码 |

**CSS 入口写法（`src/renderer/tailwind-input.css`）**

```css
@import "tailwindcss";

/* daisyUI 主题：all = 35 个内置皮肤（light 自动为默认、dark 自动跟随 prefers-color-scheme） */
@plugin "daisyui" {
  themes: all;      /* 全量 35 皮肤；每皮肤实测仅 ~1KB，全量开销可接受 */
  logs: false;      /* 关闭 🌼 横幅输出 */
}

/* 「经典」皮肤 = 自研主题之一（映射现有 :root 变量），作为应用默认 */
@plugin "daisyui/theme" {
  name: "markhunter-classic";
  default: true;            /* 应用到 :where(:root)，无 data-theme 时即生效，杜绝闪烁 */
  color-scheme: light;
  --color-base-100: #ffffff;    /* 面板底  ← styles.css --bg-panel */
  --color-base-200: #f5f7fa;    /* 页面底  ← --bg */
  --color-base-300: #eef2f7;    /* hover   ← --bg-hover（骨架值，像素级在阶段1校准） */
  --color-base-content: #26303e;/* 正文    ← --text */
  --color-primary: #3b82f6;     /* ← --accent */
  --color-primary-content: #ffffff;
  --color-secondary: #14b8a6;   /* ← --accent-2 */
  --color-secondary-content: #ffffff;
  --color-accent: #3b82f6;
  --color-accent-content: #ffffff;
  --color-error: #e5484d;       /* ← --danger */
  --radius-selector: 0.5rem;
  --radius-field: 0.5rem;
  --radius-box: 0.5rem;
  --size-selector: 0.25rem;
  --size-field: 0.25rem;
  --border: 1px;
  --depth: 1;
  --noise: 0;
}
```

> 语法正确性为调研1 实测验证（`themes: all` 产出 36 个 `[data-theme=...]` 规则；自定义主题成功编译）。**注意**：本阶段经典主题块内勿写 `--mh-*` 扩展令牌，像素级一致在阶段1 完成（此时 styles.css 尚未改名，写了也不生效）。

**`scripts/build.js` 改动点**

```js
const { build } = require('esbuild');
const { spawnSync } = require('child_process');
const path = require('path');

const root = path.join(__dirname, '..');
const cli = path.join(root, 'node_modules/@tailwindcss/cli/dist/index.mjs'); // 实测可执行
const input = path.join(root, 'src/renderer/tailwind-input.css');
const output = path.join(root, 'src/renderer/dist/tailwind.css');

// 1) Tailwind：失败立即退出（产物缺失会让 <link> 404，宁可构建失败）
const tw = spawnSync(process.execPath, [cli, '-i', input, '-o', output, '--minify', '--silent'], {
  stdio: 'inherit',
  cwd: root,
});
if (tw.status !== 0) process.exit(1);

// 2) esbuild 原样
build({ /* …原配置不变（实证 build.js:6-8 entryPoints/outfile）… */ }).catch(() => process.exit(1));
```

> 直接 `node node_modules/@tailwindcss/cli/dist/index.mjs`（即 package.json bin），比 `npx` 省 ~1s 且**禁用 npx 防联网**（调研4 明确要求）；Windows 下无 .cmd 兼容问题。顺序：tailwind 先、esbuild 后，任一失败即 exit 1 —— `release.ps1` 的 `$LASTEXITCODE` 检查自动生效。

**关键命令**

```bash
npm install                                        # 安装三个新依赖（node_modules 增量约 7MB，纯 devDependencies 不进 asar）
npm run build                                      # 一步产出 dist/bundle.js + dist/tailwind.css
# 开发 watch（任一终端跑；必须 --watch=always，否则非 TTY 下立即退出——已实测；备选 --poll=500）
node node_modules/@tailwindcss/cli/dist/index.mjs -i src/renderer/tailwind-input.css -o src/renderer/dist/tailwind.css --minify --watch=always
```

**完成标准**

1. `dist/tailwind.css` 生成（minified ≈ **130~135 KB**，调研1 实测：Tailwind 核心 5.2KB + daisyUI 35 主题 + 约 25 组件类 = 129.2KB；构建耗时 ≈ 126~251ms）。
2. **主题总数核实（本阶段硬性门禁）**：统计产物中 `[data-theme=...]` 规则数应为 **36**（35 内置 + markhunter-classic）。本计划编写时的独立实证已确认内置 35 个（见 §3.5），若实测不足 35，按 §4-Q2 追加自研主题。
3. `index.html` 加载后经典皮肤外观与 0.1.42 现状**一致**（不崩、无闪白；像素级在阶段1）。
4. `node scripts/build.js && npm run smoke`：94 项全过 + 新增 `previewListStyle`。
5. `.markdown-body` 预览列表符号未丢失（已补 list-style，见阶段1 改动；本阶段即可提前补上）。

**冒烟项**：现有 94 项全回归 + 新增 `previewListStyle`（断言 `.markdown-body ul/ol` 的 list-style 为 `disc/decimal`，防 Preflight 视觉盲区）。

**改动文件（6 个）**

| 文件 | 动作 | 要点 |
|---|---|---|

**明暗适配（随本阶段验收）**

- **CodeMirror 语法高亮**：阶段1 表层 var() 化后文字颜色跟随主题；暗色下语法高亮对比度走查（调研2 的 P2 项），必要时对高亮规则做明暗自适应（限定在 CM 主题配置内，不动 `.cm-cursor` 红线）。
- **mermaid**：按 `DARK_THEMES` 切 `theme: 'default' / 'dark'` 并**重渲染**当前图表（调研2/3）；明暗清单以实证 14 个暗色主题为准。

**关键命令**

```bash
npm run build && npm run smoke
```

**完成标准**

1. 设置弹窗出现「主题」下拉：36 选项、4 组（经典/推荐/浅色/深色）；切换任意主题**整窗即时预览**；取消/关闭还原。
2. 主题持久化：重启后保持；`themeRoundTrip` 断言通过。

### 3.1 构建集成方案（调研1 为主，调研2/4 佐证）

#### 3.1.1 依赖与版本（npm 实测可装）

```jsonc
"devDependencies": {
  // ...现有不变
  "tailwindcss":    "^4.3.3",   // npm 最新 4.3.3
  "@tailwindcss/cli": "^4.3.3", // 独立 CLI；依赖 @tailwindcss/node + @tailwindcss/oxide（Win x64 预编译 ~3MB）+ @parcel/watcher
  "daisyui":        "^5.7.18"   // 实证：5.7.18；无 peerDependencies、无运行时依赖，纯编译期 CSS 插件
}
```

- 本机 Node v24.18.0、CI Node 20 均满足 v4 要求（Node ≥20）。
- daisyUI 主题机制是 `@plugin` CSS 指令，**无需在 JS 中 import** → bundle.js 完全不受影响。
- node_modules 增量 ≈ **7MB**，纯 devDependencies，electron-builder `files: src/**/*` 白名单已限定**不进安装包**。

#### 3.1.2 文件清单（共 6 个：4 改 2 增，见阶段0 表）

产物 `src/renderer/dist/tailwind.css` 不入库：与 bundle.js 完全一致的「产物不提交」约定；`.gitignore` 的 `dist/` 同时让 Tailwind 源码扫描自动跳过产物自身。

#### 3.1.3 增量开发（npm start）如何保证 tailwind.css 存在

结论：**与 bundle.js 相同的约定——全新 clone 后先 `npm run build` 再 start**（现状本就如此）。build.js 一步产出两个产物，不存在「只有 JS 没有 CSS」的中间态。可选增强：

```jsonc
"scripts": {
  "build": "node scripts/build.js",          // 保持现状（现已含 tailwind）
  "build:css": "node node_modules/@tailwindcss/cli/dist/index.mjs -i src/renderer/tailwind-input.css -o src/renderer/dist/tailwind.css --minify --silent",
  "dev:css":  "node node_modules/@tailwindcss/cli/dist/index.mjs -i src/renderer/tailwind-input.css -o src/renderer/dist/tailwind.css --minify --watch=always"
}
```

#### 3.1.4 产物与层叠（cascade）策略

产物结构（实测未压缩）：

```
@layer properties;
@layer theme, base, components, utilities;      ← Tailwind v4 标准声明
@layer theme { …字体/间距/颜色令牌… }
@layer base   { …Preflight 重置 + daisyUI 主题变量[data-theme=X]… }
@layer utilities { …用到的工具类… }
@layer daisyui.l1 / daisyui.l1.l2 / …          ← daisyUI 组件（嵌套子层，声明在 utilities 之后）
```

**关键事实：未分层（unlayered）的作者样式，无论加载顺序与优先级，都压过所有 `@layer` 内的规则**（CSS 规范，按属性逐条裁决）。styles.css 没有任何 `@layer`，因此：

| 冲突类型 | 谁赢 | 结论 |
|---|---|---|
| styles.css 已声明的属性（`.tbtn`、`.modal`、`.markdown-body` 等） | styles.css | **现有 UI 视觉零回归（理论保证）** |
| styles.css 未声明的属性（落到 Preflight/UA 默认） | Tailwind Preflight（layered，压过 UA） | 少数默认值变化，见 §3.1.5 |
| 变量命名空间 | 互不干扰 | daisyUI `--color-*` vs styles.css `--accent/--bg/…`；**唯一例外 `--border`（§1.4 硬冲突，必须改名）** |
| daisyUI 组件类（btn/select/modal…） | 只作用于新 UI | 老 UI 不受影响 |

**加载顺序：`tailwind.css` 必须在 `styles.css` 之前**（preflight 作底 + 变量冲突时后定义者胜；调研1/4 一致）。**0.1.43 不建议把 styles.css 并入 `@layer`**（未分层优先级高于所有 layer，并入反而会被 preflight 压过；调研1/4 一致）。

组件按使用裁剪（实测）：HTML 里没用到的组件全部不出现在产物中——体积只随实际用到的组件增长。

#### 3.1.5 Preflight 实际默认值变化（已逐条核实）

| Preflight 规则 | 影响 | 处置 |
|---|---|---|
| `ol, ul, menu { list-style: none }` | **`.markdown-body` 列表丢失项目符号/编号**（`styles.css:758` 只设 margin/padding） | **必补 2 行**：`.markdown-body ul{list-style-type:disc} .markdown-body ol{list-style-type:decimal}` |
| `img, svg, video { display:block }` | 预览内联图片变块级（换行） | 大概率可接受；不接受则补 `.markdown-body img{display:inline}` |
| `html { line-height:1.5 }` | 未设 line-height 的元素行高 1.5 | body 补 line-height，审计确认 |
| `*{margin:0;padding:0;box-sizing:border-box;border:0 solid}` | 与 styles.css 19 行同值同向 | 无冲突 |
| `h1-h6{font-size:inherit;font-weight:inherit}`、`hr`、`table`、`button,input{font:inherit}` | 均被 styles.css 对应规则覆盖 | 无冲突 |
| v4 已移除按钮 `cursor:pointer`（[tailwindcss#15773](https://github.com/tailwindlabs/tailwindcss/issues/15773)） | 小按钮悬停无手型 | 显式补 `button{cursor:pointer}`（如需） |
| daisyUI base：`rootcolor`（html 底色跟随主题）、`rootscrolllock`、`scrollbar`（scrollbar-color） | styles.css `html,body{overflow:hidden}` unlayered 必胜；`::-webkit-scrollbar` 优先于 scrollbar-color | 无冲突；rootcolor 让 `data-theme` 后 html 底色跟随主题，对换肤有利 |

> 结论：唯一必改样式回归是**列表符号 2 行**；其余进审计清单。

#### 3.1.6 安全项兼容性（CSP / sandbox，实测核实）

- daisyUI v5 是 100% 编译期 CSS：主题切换 = 属性切换触发 `[data-theme=X]` 选择器，组件无运行时 JS、不注入内联 `<style>`。CSP `style-src 'self' 'unsafe-inline'` 原样足够（`'unsafe-inline'` 本来是为现有 `documentElement.style.setProperty('--scrollbar-width')` 这类内联样式服务的）。
- daisyUI base 唯一的 data: URI（`--fx-noise` 噪声纹理）属 `img-src` 范畴，CSP 已含 `data:`，无碍。
- `sandbox:true / contextIsolation:true` 与 CSS 无关；`<link>` 走 file:// 相对路径，与现有 styles.css 同一加载通道。

#### 3.2.2 ⚠️ `--border` 命名冲突（唯一硬冲突，必改）

- **实证（本次核实）**：daisyui@5.7.18 每个主题块首行均有 `--border: 1px`（cupcake/pastel/silk/caramellatte 为 `2px`）——语义是**边框宽度**；MarkHunter `styles.css:10` 的 `--border: #e3e8ef`——语义是**边框颜色**。

- **处置：MarkHunter 侧改名 `--mh-border`**（推荐全量语义变量改 `--mh-*` 前缀，见 §4-Q7）。调研2 将其列为最高风险项，调研4 列为「唯一硬冲突 C1」。

- `DEFAULTS.theme = 'markhunter-classic'`；`ALLOWED_KEYS` 加 `'theme'`（两处缺一不可，实证 `settings.js:6/24`）。
- 主进程 `THEME_NAMES` 白名单（36 个合法值）：**非法值静默丢弃**，延续 S6 安全风格。
- `DARK_THEMES`（14 个暗色，实证清单 §3.2.7）：供主进程 `BrowserWindow.backgroundColor` 与 mermaid 明暗切换。

#### 3.3.2 主题分组推荐表（设置下拉 optgroup）

| 分组 | 皮肤（36 个） | 说明 |
|---|---|---|
| 经典 | `markhunter-classic` | 默认；老用户观感零变化 |
| 推荐 | `light` `dark` `night` `dracula` `nord` `synthwave` `corporate` `business` | 编辑器场景高对比度优先 |
| 浅色（其余 20 个） | cupcake bumblebee emerald retro cyberpunk valentine garden lofi pastel fantasy wireframe cmyk autumn acid lemonade winter caramellatte silk aqua* forest* | 浅色全集 |
| 深色（其余 11 个） | halloween black luxury coffee dim sunset abyss | 深色全集 |

> *aqua/forest 为 `color-scheme: dark`，浅色组内按品牌色归类，最终分组以实施时色板为准；中文 label 格式如 `night · 深蓝夜`。

#### 3.3.3 防闪白（双层）

1. **主进程**：按 `DARK_THEMES` 设 `BrowserWindow.backgroundColor`（暗色主题深色底，防首帧白闪）；
2. **preload 同步**：`sendSync('theme:get-sync')` 在渲染脚本执行前设 `data-theme`（CSP 禁内联脚本，故走 preload，早于任何渲染脚本/首帧）。

叠加阶段0 的静态 `<html data-theme>` + `default:true`，共四重保障，无 FOUC。

#### 3.3.4 面板交互

- `openSettings()` 追加 `.field-select` 下拉；**`change` → `applyTheme` 即时预览**，取消/关闭还原——天然就是最真实的色板预览，**无需额外色板格子面板**。
- 暗色跟随系统：**本期只做手动选择（推荐）**；二期做 `nativeTheme` 监听 + system 伪值/独立开关，已在计划中预留（§4-Q3）。

### 3.4 回归风险清单（调研4）

#### 3.4.1 冒烟影响清单（最优先）

通读 `scripts/smoke.js`（1611 行）：94 项 = 11 项 API/主进程直测 + 80 项 UI step + 2 项剪贴板片段。**没有一项直接断言颜色**；与样式/布局相关的只有 4 个探测型用例：

| 用例 | 探测方式 | 风险 |
|---|---|---|
| `caretVisible` | 扫 styleSheets 找 `.cm-cursor{visibility:visible}` 规则 | **`.cm-cursor` 必须保持顶层字面量**（不进 @layer/@media/变量间接） |
| `userSelect` | computed `user-select:text` | 低 |
| `scrollbarSetting` | `:root` 的 `--scrollbar-width` ∈ [6,40] | **`--scrollbar-width` 保持 `:root` + app.js 内联覆盖** |
| 几何系（dividerPos/dividerDrag×2/dividerDblclick/dividerResize/viewerScrollFull/selectSameLine） | 几何断言（容差 ±10/±6px） | 现有 94 项不动，容差足够 |

**判定：正确实现下 0 项必然失败**；失败风险全部来自重构动作而非 tailwind/daisyUI 本身。**三条红线**：① 不改语义类名（`.tab.pinned/.selected/.tree-node/.caret.open/.current/.hidden/.ctx-item` 等）；② `.cm-cursor` 顶层字面量；③ `--scrollbar-width` 保持 `:root` + 内联覆盖。断言修正建议：现有 94 项不动；新增 `themeRoundTrip` + `previewListStyle`（§2-阶段2 表）。

#### 3.4.2 层叠冲突清单

- **唯一硬冲突 C1：`--border` 同名**（§3.2.2，实证），必须改 `--mh-border`。
- 其余 preflight 冲击见 §3.1.5 表；`img` 块级可接受；按钮 cursor 提示按需补。
- **加载顺序：tailwind.css 在 styles.css 之前**；0.1.43 不把 styles.css 并入 `@layer`。
- 多主题生效前提：styles.css 自有变量与 daisyUI 令牌**不同名不联动**，需 `:root` 一层 var 桥接（§3.2.3 表）。

#### 3.4.3 构建链与 CI

- build.js 新增一步 spawn `@tailwindcss/cli/dist/index.mjs`（**禁用 npx 防联网**）。
- 产物 `src/renderer/dist/tailwind.css` 已被 `.gitignore` 的 `dist/` 覆盖，无需改 gitignore。
- electron-builder `files: src/**/*` 已覆盖，但显式 files 下是否引用 .gitignore 有不确定性 → **发布前 `--win --dir` + 列 asar 验证**，缺则显式加 include。
- **release.yml 无需改动**（`npm ci` + `node scripts/build.js` 已覆盖；CI Node 20 达标）。

#### 3.4.4 体积/性能与依赖

- 全量 35 主题 + preflight + 组件层 ≈ 压缩 130~135KB（调研1 实测，§3.1.7），不足 9.1MB bundle 的 1.5%；主题切换仅换 CSS 变量（颜色 repaint，无重排）。全主题优于运行时动态加载；可用 `exclude` 裁掉未用组件（二期按需）。
- Tailwind v4 需 Node ≥20（本机 24 ✓、CI 20 ✓）；daisyUI v5 仅兼容 v4；v4 输出含 oklch/color-mix/@property，**Electron 43（Chromium ≥140）完整支持**（实证：daisyUI 主题变量全部为 oklch，Chromium 111+ 即支持，无兼容问题）。
- 建议**精确锁定版本**：CSS 产物跨小版本会变，锁定保证回归可比。

#### 3.4.5 回归流程（四阶段门槛）

P1 纯引入 → P2 变量桥接 → P3 多主题 → P4 打包验证；每阶段 `node scripts/build.js && npm run smoke` + 手工清单（35+ 主题抽查 8 个代表，11 项检查）。
