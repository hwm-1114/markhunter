## 一、实测复现（16 项）

### A1【实测·严重·静默数据丢失】分段大文件的自动预读进了撤销历史 → Ctrl+Z 后自动保存把文件截断
- **现象**：打开 >4MB 文件（`kind='chunked'`），滚到底部触发分段预读，随后按 Ctrl+Z：文档回退一整段（2MB），占位标记回归，`chunk.complete` 仍为 `true` 所以不会重新补读；800ms 后自动保存把残缺文档整体写盘。
- **实测数据**：文件 5,388,889 B → 全部加载后文档 5,388,889 字符 → Ctrl+Z 后 2,097,207 字符（`MH-CHUNKED` 标记回归）→ 自动保存后**磁盘仅剩 2,097,152 B（尾部 3.29MB 永久丢失）**。
- **定位**：`src/renderer/tabs.js:701-726`（`appendChunkText` 的 `view.dispatch({changes})` / `state.update` 未加 `Transaction.addToHistory.of(false)`）、`tabs.js:1215-1218`（`c.complete===true` 时跳过补读直接写盘）。同类：`tabs.js:1677-1680`（外部修改重载被撤销后可把旧内容写回，覆盖外部修改）、`tabs.js:457`（查看器换窗）。
- **建议**：① 分段追加/程序化重载统一 `annotations: Transaction.addToHistory.of(false)`；② `doSaveNow` 加不变量校验：`chunked && t.state.doc.length < t.chunk.loaded` → 拒绝写盘并补读（双保险）。

### A2【实测·严重】CRLF 文件只要保存一次就被整篇改写为 LF
- **现象**：Windows 下 `.bat/.ps1/.csv/.md` 等 CRLF 文件，打开后（CM6 默认按 `\r\n|\r|\n` 切行，`doc.toString()` 以 `\n` 连接）任意一次自动保存即把全文行尾改成 LF；`.bat/.ps1` 可能出现执行异常，git 出现整文件 diff。
- **实测数据**：写盘内容 `line1\r\nline2\r\nline3\r\n` → 打开后文档已无 `\r` → 编辑 1 个字符 → 自动保存后磁盘为 `"Xline1\nline2\nline3\n"`。
- **定位**：`tabs.js:211-245`（`makeState` 未设行分隔符）、`tabs.js:1218-1223`（`writeFile(doc.toString())`）、`tabs.js:1238-1252`（流式写同样写 `\n`）；全仓无 `EditorState.lineSeparator` / `\r\n` 还原逻辑。
- **建议**：打开时记录 `tab.crlf = /\r\n/.test(content)`（或 `EditorState.lineSeparator.of('\r\n')`），保存前按标记还原；至少对 `.bat/.cmd/.ps1` 强制保留 CRLF。

### A3【实测·严重】>256MB「只读」查看器实际可编辑，改动静默丢弃
- **现象**：横幅显示「只读」，但文档状态并非只读，可直接输入；输入后 `saveViewerRegion` 因 `!t.editing` 直接 `return true`（假装保存成功），随后翻页/跳转/外部重载会把这段文字无声丢弃。
- **实测数据**：286MB 文件 → `tab.kind='viewer-lg'`、`tab.readOnly=false`、`view.state.readOnly=false`、横幅 `0 B ~ 8.00 MB / 286.10 MB（0% · 只读）`。CM6 语义旁证：`contenteditable` 只由 `editable` facet 决定（`@codemirror/view/dist/index.js:8273`），输入处理才看 `state.readOnly`（同文件 4153/5108/5139/7638）——即 `state.readOnly=false` 时用户可以打字（`contenteditable` 属性本身不作为判据）。
- **定位**：`tabs.js:353-367`（`openViewerTab` 不设 `tab.readOnly`）→ `tabs.js:832`（切换时 `reconfigure(EditorState.readOnly.of(!!tab.readOnly))` 把只读改回可编辑）；`tabs.js:574-575`（`!t.editing` 时静默返回 true）。
- **建议**：`switchTab` 中 `const ro = tab.kind === 'viewer-lg' ? !tab.editing : !!tab.readOnly;`；`saveViewerRegion` 未启用区域编辑时应返回 `false` 并提示。

### A4【实测·高】Python 面板：单批超过 3000 行时整批输出丢失
- **现象**：一次打印几千行的程序，面板里**什么都不显示**（只看到命令行回显与退出行）。
- **实测数据**：打印 2000 行 → 2007 个 span（正常）；打印 **6000 行 → 仅 3 个 span / 22 字符**（整批丢失）。机制由算术唯一确定：`excess = 现有子节点 + 本批行数 - 3000`，本批行数 > 3000 时循环次数必然超过现有子节点数，`output.removeChild(output.firstChild)` 在 `firstChild === null` 时抛 `TypeError`（探针未捕获到该异常事件，但「整批消失、只剩 start/exit 两行」的观测与推导完全一致）。
- **定位**：`src/renderer/python.js:26-52`（尤以 `45-49`）。
- **建议**：`const excess = Math.min(output.childElementCount + frag.childElementCount - 3000, output.childElementCount);`（或 `while (excess-- > 0 && output.firstChild)`），并把上限判断改成「只保留最后 3000 行」。

### A5【实测·高】删除文件后标签保存把它写回磁盘 —— 删除静默失效
- **现象**：对有未保存改动的文件执行「🗑 删除文件」→ 文件从树中消失、标签关闭，但**磁盘上文件又被创建回来**（内容为内存中的最新版），刷新目录后它再次出现。
- **实测数据**：删除后 `stat` 失败（确已删除）→ 执行标签关闭链路后 `exists=true`，内容 `"v1\nDIRTY-EDIT\n"`。
- **定位**：`src/renderer/tree.js:651-666`（`await window.api.remove()` 后 `onClosePath(path, null)`）→ `src/renderer/app.js:514-537`（`editor.closeByPath(p,false)`）→ `src/renderer/tabs.js:997-1005`（`if (tab.dirty) saveNow(tab)`，fire-and-forget）→ `tabs.js:1218-1223`（写盘；路径仍在侧栏根内 → `security.js` 放行）。
- **建议**：删除路径不要触发保存 —— `closeByPath/closeTab` 增加 `{ save:false }`（或删除前 `tab.dirty=false`）。

### A6【实测·高】对比大文件：单侧大块新增超过 ~12.5 万行 → 抛异常，对比视图空白且标签栏不刷新
- **现象**：「🔀 对比」一个 15 万行的文件与空内容（或整段重写的文件）→ 抛出 `RangeError`，对比区空白；由于异常发生在 `renderDiff` 内，`switchTab` 后续的 `renderTabs/onTabSwitch` 全部跳过，标签栏不出现该标签，但 `getActiveTab()` 已经是这个 diff 标签 → 界面状态错乱。
- **实测数据**：`d1_thrown="RangeError: Maximum call stack size exceeded"`、`#diff-host` 内容长度 0、标签栏 0 项、`getActiveTab().name="🔀 a.txt ↔ b.txt"`；Node 侧旁证：本项目 `diff@9.0.0` 对空↔15 万行返回**单个 15 万行 added 片段**，`arr.push(...arr150k)` 抛 RangeError，spread 参数上限实测 **≈125,103**。
- **定位**：`src/renderer/diffview.js:48-49`（`dels.push(...splitLines(...))` / `adds.push(...splitLines(...))`）。
- **建议**：改为 `for (const l of splitLines(parts[i++].value)) dels.push(l);`；并给 `renderDiffTab` 包一层 try/catch，失败时给出可读提示而不是留空白。

### A7【实测·中】AI/对比读取「分段文档」既没剥离占位标记、也没补读全文
- **现象**：>4MB 文件以分段模式打开时，AI 工具 `read_document`、「📄 全文」附加上下文、文档对比拿到的都是**已加载的一段 + 内部占位注释**。
- **实测数据**：5.33MB 文件 → `read_document` 返回 2,097,207 字符，末尾为 `<!-- MH-CHUNKED 已加载 2.00 MB / 5.08 MB，滚动到底部自动加载更多 -->`。
- **定位**：`src/renderer/app.js:257`（`return tab.state.doc.toString();`）、`src/renderer/ai-panel.js:295`（`pendingContext = tab.state.doc.toString()`）、对比路径 `app.js:1118/1137/1151`。对照：预览 `preview.js:321`、保存 `tabs.js:1218` 均已 `stripChunkMarkers` —— 与 `AGENTS.md` 红线（任何写盘/预览/AI 读文档路径都必须先 strip，必要时补读）不一致。
- **建议**：AI/对比读取前统一走 `stripChunkMarkers(...)`，并对未 complete 的 chunked 标签先 `ensureFullyLoaded`（或明确告知模型「仅前 N MB」）。

### A8【实测·中】「🔒 只读」标签（跨窗口共享锁）可被 AI 写入并自动保存
- **现象**：第二个窗口打开同一文件会被自动设为只读（D2 协调），但 AI 的 `apply_snippet/insert_text/replace_document` 走程序化 dispatch，不受 `EditorState.readOnly` 限制；随后自动保存把改动写盘，反过来还会让「编辑窗口」弹出外部修改确认。
- **实测数据**：只读标签（`tab.readOnly=true`）执行 `applySnippet('AI WROTE THIS\n','full')` → `dirty=true`，1.5s 后磁盘内容变为 `"AI WROTE THIS\n"`。
- **定位**：`tabs.js:1549-1563`（`applySnippet` 无 readOnly 校验）对照 `tabs.js:1535-1539`（`insertAtCursor` 有）；`app.js:265/272/279`（AI 工具直接调用）。
- **建议**：`applySnippet` 开头加与 `insertAtCursor` 同款守卫（或对 `tab.readOnly` 拒绝并提示「该文件在另一窗口编辑中」）。

### A9【实测·中】AI 徽标「切换模型」不生效（改了磁盘、不改内存）
- **现象**：点徽标选「DeepSeek 推理版」后，徽标仍显示旧模型；下一次提问仍按旧模型发请求；随后打开设置点保存还会把旧模型写回。
- **实测数据**：点击后磁盘 `aiModel="deepseek-reasoner"`，但 `app.state.settings.aiModel="deepseek-chat"`、徽标文案 `deepseek-chat · ↑0 ↓0`。
- **定位**：`src/renderer/ai-panel.js:229-264`（`pick()` 丢弃 `setSettings` 返回值）；`getSettings()` 取自 `app.js:26` 的缓存，只在设置弹窗保存（`app.js:995`）与跨窗口广播（`app.js:1305`）时刷新；`ai-panel.js:172-176` 用该缓存发请求。
- **建议**：`app.state.settings = await window.api.setSettings({aiModel})`；或给 ai-panel 传一个 `refreshSettings()` 回调。

### A10【实测·中】Esc 关弹窗仍会顺带收起底部面板（v0.2.4 声称已修）
- **现象**：底部面板（文件内搜索/Python）处于展开时打开任意弹窗（如设置），按 Esc：弹窗关闭 **且** 底部面板被收起。
- **实测数据**：Esc 前 `panelOpen=true, modalOpen=true` → Esc 后 `modalHidden=true, panelCollapsed=true`。
- **定位**：`src/renderer/ui.js:299-307` 的 document keydown 先执行（`closeModal()` 给 `#modal-mask` 加回 `hidden`），随后 `src/renderer/app.js:1293-1300` 再读取 `modalOpen`（此时已为 false）→ 判定「没有弹窗」→ 收起面板。监听注册顺序决定，属于必然结果。
- **建议**：`ui.js` 的 Esc 处理 `e.stopPropagation()`／置标记，或 `app.js` 改用 `e.defaultPrevented` 判定。

### A11【实测·中】Python 输出被管道分块切断，中文出现替换符
- **现象**：程序一次性写入大段中文（非按行 flush）时，`chunk.toString('utf8')` 会把跨块的多字节字符切成 `U+FFFD`。
- **实测数据**：`sys.stdout.write("中"*100000)` → 面板出现 **8 个 `\uFFFD`**（按行 flush 的输出不受影响，实测 2 万行中文 0 个）。
- **定位**：`src/main/python.js:271-276`（两处 `d.toString('utf8')`）。
- **建议**：用 `new (require('string_decoder').StringDecoder)('utf8')` 按流解码（stdout/stderr 各一个实例）。

### A12【实测·中】同一文件不同大小写路径 → 开出两个标签
- **现象**：`openFile` 仅按字符串严格比较去重，Windows 大小写不敏感下同一文件可出现两个标签，先后保存互相覆盖；目录拖拽移动后新路径还会被**小写化**（见 B7），进一步触发该问题。
- **实测数据**：`openFile('.../case.md')` 后再 `openFile('.../CASE.MD')` → 同一文件的标签数 = 2。
- **定位**：`tabs.js:283`（`tabs.find(t => t.path === path)`）、`tabs.js:1432`（`findTabByPath`）；对比 `tree.js` 全用 `normalizeKey`。
- **建议**：去重/查找统一走规范化键（`path.toLowerCase()`）。

### A13【实测·低】切换标签后光标位置丢失
- **现象**：在 A 文件把光标移到中部，切到 B 再切回 A，光标回到「上次编辑处」（常见为首行），而不是离开时的位置（滚动位置有专门恢复逻辑，光标没有）。
- **实测数据**：切换前 `head=145` → 切回后 `head=0`。
- **定位**：`tabs.js:228-242`（updateListener 只在 `docChanged` 时回写 `activeTab.state`，纯选区变化不回写）→ `tabs.js:824`（`view.setState(tab.state)`）。
- **建议**：在 `switchTab` 离开标签时把 `view.state.selection` 存回 `tab.state`（`tab.state = view.state`），或在 updateListener 里对 `selectionSet` 也回写。

### A14【实测·低】文件内查找无上限、无防抖：大文件常见词会拖死渲染进程
- **现象**：`find-input` 的 `input` 事件直接 `runSearch()`（只有「文档变化」路径走了 250ms 防抖），匹配数无上限：每处匹配 = 1 个结果 DOM 行 + 1 个 CM 装饰。
- **实测数据**：20,000 处匹配 → 161ms 同步阻塞 + 20,000 行 DOM；按线性外推 50 万处 ≈ 4s 卡死（4MB 日志里搜常见词很容易到这个量级）。全局搜索有 3000 上限，文件内查找没有任何上限。
- **定位**：`find.js:224`、`find.js:33-43`（`collect`）、`find.js:48-52`（`applyHighlights`）、`find.js:86-100`（逐匹配建行）。
- **建议**：输入防抖（复用 `ui.js` 的 `debounce`）+ 匹配上限（如前 500 行 + 「还有 N 处」）+ 装饰数上限。

### A15【实测·低】预览外链图片被 CSP 拦截，永远显示不出来
- **现象**：`![](https://…)` / `![](http://…)` 的图片在预览里是破图；`resolveImgSrc` 特意把 http(s) 原样透传，但 CSP 的 `img-src 'self' data: file:` 不含 http(s)。
- **实测数据**：本地 http 服务 1×1 PNG → `img.naturalWidth=0`，`securitypolicyviolation: "img-src http://127.0.0.1:18434/x.png"`（两次）。
- **定位**：`src/renderer/index.html:5`（CSP）vs `preview.js:94-111`（`resolveImgSrc` 透传 http(s)）、`preview.js:332-346`（赋给 `img.src`）；图片查看器 `openViewer({src:'https://…'})` 同样受限。
- **建议**：明确取舍 —— 要么 CSP 加 `https:`（并接受外链图片加载），要么在渲染前把外链图替换为占位提示（避免用户以为图挂了）。

### A16【实测·中】Python 进程管理竞态：旧进程的退出回调清空新进程引用 → 「■ 终止」失效、进程泄漏
- **现象**：连续启动两次运行（或两个窗口各跑一次脚本）时，被 `taskkill` 杀掉的旧进程 `close` 事件晚到，其闭包无条件执行 `currentProc = null`，把**新进程**的引用抹掉；此后 `python:kill` 直接返回 `false`（终止按钮无效）、退出应用也无法回收；同时面板被旧进程的 `python:exit` 覆盖，状态显示「已退出」而实际还在跑。
- **实测数据**：先跑 a.py（sleep 2）再跑 b.py（sleep 6）→ 1.2s 时面板显示 `退出码 1（0.13s）`（旧进程事件）→ `killPython()` 返回 **false**；b.py 直到 6.10s 自然结束才显示 `已完成（6.10s）`。
- **定位**：`src/main/python.js:254-256`（`disposeCurrentProc()` 只摘 `data` 监听，`close/error` 仍在）、`src/main/python.js:286`（`sendExit` 内无条件 `currentProc = null`）、`src/main/python.js:303-309`（`python:kill`）。
- **建议**：`sendExit` 改为 `if (currentProc === child) currentProc = null;`；`disposeCurrentProc` 里 `old.removeAllListeners()`。

### 5.2 【严重·实测】只要用户"用过一次"，右键目录就 100% 失效

### 5.3 根因（代码级，可解释全部观测）

```js
// src/renderer/app.js
window.api.onOpenDir((dir) => { externalDir = dir; if (bootDirSettled) openDirFromPath(dir); });  // :641-644
...
if (externalDir) { await openDirFromPath(externalDir); } else { /* 恢复 lastDirectory / sidebarRoots */ }  // :1331
bootDirSettled = true;                                                                            // :1350
```
主进程在 `did-finish-load` 推送（`main.js:65-72`）。渲染端 boot 已经越过 `:1331` 的判定、正卡在 else 分支的 `await openDirFromPath(...)`（一次 `readTree` IPC 往返）时事件到达 → 监听器把 `externalDir` 写进去，但 `bootDirSettled` 仍是 `false`：既不当场执行，也不会被 `:1331` 再判一次 → **事件被静默吞掉**。

- 无历史时（场景 A）else 分支没有任何 `await`，`bootDirSettled=true` 在同一同步块内完成 → 事件随后到达被直接执行 → 这就是"只有全新安装的用户能用"的原因。
- 场景 G 表面看恢复窗口只有 1 次 IPC，但失败 4/4 确定性成立：事件的投递点稳定落在 `readTree` 那次 await 上（同一队列顺序），不是随机抖动。
- 这也解释了 v0.2.2「实测通过」为何没覆盖到：当时验证路径是单目录 + 空会话。

### 5.4 附带发现

1. **用户点右键启动的是 0.1.46 旧安装版**：`F:\MarkHunter\resources\app.asar` 内 `package.json` 的 `version = 0.1.46`（落后仓库 0.2.5 共 9 个版本）。其 `main.js` 无 `extractDirArg`/`second-instance`/`win:new`；`app.js` 无 `bootDirSettled`/`externalDir`/多根侧栏/对比/AI 工具等。用 CDP 实测该版本：右键目录能改「目录标签」，但侧栏树仍停在旧目录、并把上次会话的标签一并打开（半失效的并发竞态）。**判断右键体感前应先升级安装版**。
2. `--dir` 指向**不存在路径**时没有任何提示（静默停在"未打开目录"）。
3. 连点右键 → 不停新建窗口（实测 1→5），且每个新窗口都会**恢复上次会话的标签**，"右键打开某目录"并不是一个干净窗口。
4. 右键菜单缺少文件/盘符入口；`.md` 未做文件关联。

### 5.5 修复方案（建议并入 0.3.0 Phase 0）

1. **preload 缓冲事件**（消除"注册前到达即丢"这一类问题）：
   ```js
   let pendingOpenDir = null;
   let openDirCb = null;
   ipcRenderer.on('open-dir', (_e, d) => { pendingOpenDir = d; if (openDirCb) openDirCb(d); });
   // onOpenDir(cb) 时若 pendingOpenDir 已存在，立即回调一次；另暴露 takeOpenDir() 供主动拉取
   ```
2. **boot 末尾补一次生效判定 + 主动拉取**（修当前这个"吞事件"窗口）：
   ```js
   bootDirSettled = true;
   const want = externalDir || (await window.api.takeOpenDir());
   if (want && normKey(state.rootDir || '') !== normKey(want)) await openDirFromPath(want);
   ```
3. `--dir` 生效时不恢复上次会话（右键打开 = 干净窗口）；把被替换掉的会话缓存进"最近关闭"，需要时可一键恢复。
4. 主进程把"待应用目录"作为状态保存，渲染端**拉取式**获取（推送 + 拉取双保险），`second-instance` 沿用。
5. 安装器补 `Drive\shell`（盘符右键）；可选 `*\shell`（文件右键 → `--dir` 传父目录并打开该文件）；坏路径给明确 toast。
6. 冒烟新增：`rcDirColdStart`（有历史状态下 `--dir` 必须生效）、`rcDirSecondInstance`、`rcDirBadPath`、`rcDirDriveRoot`、`rcDirCleanWindow`。
