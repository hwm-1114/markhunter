## 三、分项计划

## 需求 1：跨目录树定位（L）

### 3.1.1 现状证据

- **外部文件树定位 = 静默无操作**：唯一定位入口 `reveal(path)`（tree.js:307-351），前置守卫 tree.js:312 `if (targetKey === rootKey || !targetKey.startsWith(rootKey)) return;`，外部路径直接返回；tree.js:314 另有 `/` 边界判定防 `F:/ab` 误匹配 `F:/a`。
- **全部接线点都走 reveal**：标签切换 app.js:63、树内点击 app.js:269、全局搜索跳转 app.js:355、拖拽打开 app.js:673、AI `open_file` app.js:152（`open_file` 本身被 S8 限制为 rootDir 内相对路径，app.js:138-153）。跨项目打开主要来自**拖拽、全局搜索、会话恢复**（app.js:242-262，lastSession 可含任意路径）；收藏仅收藏目录（favorites.js），点击收藏目录走 `openDirFromPath` 切换工作目录（app.js:319-322）。
- **rootDir 语义面**：全局搜索范围 globalsearch.js:14,30 → 主进程 search.js:41-44；新建文件位置 app.js:342 → tree.js:297-303（getTargetDir）；收藏高亮 favorites.js:140-147；AI 工具边界 app.js:116-153。
- **安全模型**：主进程 `currentRoot`（security.js:6）仅经 `fs:set-root`（ipc.js:37-40）由 `openDirFromPath` 设置。S1 `isApproved` = `isInside(currentRoot, p) || approvedSet.has(realpath(p))`（security.js:52-57）；**approve 只发生在 `fs:read-file` 成功时**（ipc.js:121）→ 外部文件一经打开，保存/重命名/删除/运行仍可用；`requireApproved` 有父目录兜底（security.js:61），但**目录从未被 approve** → 外部目录新建文件会被拒（正确行为，需保持）。
- **对任务描述的一处纠正**：rootDir **不**影响 Python cwd——主进程 `python:run` 的 `cwd` 是 `path.dirname(filePath)`（python.js:174-175），rootDir 仅作 isApproved 门槛（python.js:152）。
- **关键前提**：`fs:read-tree` **不受路径校验限制**（ipc.js:79-80 注释"目录树需可自由浏览"）→ 树可自由读取任意目录，方案 B 零主进程改动即可成立。
- **树内部结构**：`nodeMap`（path → {row, children, isDir}，tree.js:30,87）、`expanded`（setRoot 时重置，tree.js:40）、`loadChildren(dirPath, force)`（tree.js:129-158，懒加载 + `loadingDirs` 并发去重）、`select()`（tree.js:165-170）、右键菜单 `showCtx`（tree.js:172-190）、`getTargetDir`（tree.js:297-303）、`refreshSelected`（281-294）/`refreshNode`（268-279）。

### 3.1.2 方案对比与推荐

| 方案 | 体验 | 实现复杂度 | 对现有功能副作用 | 与 S1/security 兼容性 | 结论 |
|---|---|---|---|---|---|
| **A 自动切工作目录** | 树立即真实定位；但工作区被劫持、多文件打架 | 低（1.5–2h） | **高**：全局搜索范围/新建位置/收藏高亮/lastDirectory/AI 边界全翻转；旧 root 新建静默被拒 | 差：currentRoot 漂移 | **否决为自动行为** |
| **B 外部虚拟分支** | 任意文件可定位；rootDir 不变；按真实路径链展示 | 中（7–9h） | **低**：仅树多渲染一个分支 | **优**：不改 currentRoot/approvedSet | **推荐** |
| C 指示条 | 只告知位置、不能树内定位 | 低（约 1h） | 无 | 优 | 作补充提示 |
| D1 外部区右键「切换工作目录到此目录」 | 用户主动把外部目录变成工作区 | 低（0.5h） | 用户触发时才发生 | 与 A 相同但由用户决定 | **推荐补充（逃生舱）** |
| D2 多根工作区 | 最完整 | 高（数天） | 高（搜索/会话/设置） | 需新增安全维度 | 超范围 |

**推荐：方案 B（链式外部虚拟分支）+ D1（外部区右键切换工作目录）+ C 轻量提示（激活外部文件 toast 一次）**。
理由：唯一同时满足"任意文件树内定位"且零改动 rootDir 语义的方案；关键前提（readTree 不受限、外部文件已 approve）已具备；心智模型贴近 VS Code；可降级——若链式超预期，降为"外部文件扁平列表"（不建中间目录链），工作量降至约 3h 仍满足需求原文。

### 3.1.3 关键设计

- **冲突规避证明**：外部文件在 rootDir 外 ⇒ 其**所有祖先目录都在 rootDir 外**（否则文件也在 rootDir 内，矛盾）。真实树只渲染 rootDir 子树（tree.js:52-55），外部链（盘符根 → … → 父目录）与真实树渲染空间**无交集**，`nodeMap` 以真实路径为 key 不会冲突。唯一特判：**虚拟根行用合成 key（`'\u0000ext\u0000'`，绝不可能是真实路径）**。
- **去重**：`externalOpen` Map 按 `normalizeKey(dir)` 归组（dir → {path, files:Set}），同目录多文件一条链，同盘多目录共享盘符根。
- **主进程零改动**：readTree 不受限（ipc.js:80）、外部文件 approve 机制已存在（ipc.js:121）、settings 白名单无需新键。

### 3.1.6 冒烟测试（+9 项）

## 需求 3：右键粘贴为纯文本（M）

### 3.3.1 现状证据

- **编辑区无右键菜单**：`src/main/main.js` 全文无 `Menu` 模块、无 `webContents.on('context-menu')`（Electron 默认不显示右键菜单，需自行构建）；`tabs.js` 只在 `view.dom` 注册 `paste` 监听（L424-434，仅拦截图片），无 `contextmenu`。
- **全局唯一右键菜单是树的 `#ctx-menu`**（index.html:158），由 tree.js `showCtx/renderCtxMenu/hideCtx`（L172-228）驱动：`renderCtxMenu(x,y,items)` 渲染 `{label, fn, sep?, danger?}` 并做窗口边界 clamp（L211-213）；全局 `document click → hideCtx`（L225）；`document contextmenu` 非 `.tree-node` 即 hideCtx（L226-228，**不 preventDefault**）；样式 styles.css:653-674（z-index:200）。`ui.js` 中**无**通用菜单函数，`renderCtxMenu` 是 `createTree` 闭包私有。
- **剪贴板现状**：主进程已有 `clipboard:write-image`（main.js:107-113）；preload.js:17 暴露 `copyImage`；**无读文本 IPC**。图片粘贴走 `pasteImages()`（tabs.js L424-434 拦截 `image/*` 后保存并插入 `![](./xxx)`）；文本粘贴不拦截走 CM6 默认。现成插入函数：`insertAtCursor(text)`（tabs.js:470-477，含 `view.focus()`）、`applySnippet`（480-491）。
- **CSP 不是阻碍项**（index.html:5 `script-src 'self'` 不控 Clipboard API）；真正约束是 `navigator.clipboard.readText()` 需窗口焦点 + `clipboard-read` 权限，且 **Electron 40+ 已开始弃用渲染进程剪贴板直读、官方指引把剪贴板移到 preload/主进程**（本项目是 Electron 43，正落该弃用区间）→ 渲染进程直读属脆弱路径。

### 3.3.2 设计决策

| 决策点 | 方案对比 | 推荐 |
|---|---|---|
| 菜单实现 | A. 抽通用菜单模块（`ui.js` 加 `openCtxMenu(x,y,items)/hideCtxMenu()`，tree.js 委托）——单一菜单元素、单一隐藏路径、零新增样式，且**服务需求 4**；B. tabs.js 独立实现——不动 tree.js 但双套菜单共享同一 `#ctx-menu` + document 监听，隐藏语义易打架 | **A** |
| 读剪贴板 | `navigator.clipboard.readText()`（需焦点+权限，Electron 收紧，失焦即 NotAllowedError）vs **新增 IPC `clipboard:read-text`（主进程 `clipboard.readText()`，读 Windows CF_UNICODETEXT = text/plain 表示，天然无富文本，无焦点/权限约束，与 write-image 同模式）** | **IPC**（main.js 加 3 行 handler + preload 加 1 行） |
| 「纯文本」定义 | **默认：系统剪贴板 text/plain 内容**（Word/浏览器复制富文本的 text/plain 表示已剥离 HTML/样式）；Markdown 符号剥离（`**x**`→x、行首 `#`、`[t](url)`→t）列为 **v2 可选设置默认关**（有损且歧义大，会误伤正文合法符号；若做须进 settings 白名单） | v1 只做默认 |
| 与图片粘贴共存 | 图片分支只在原生 `paste` 事件触发；右键菜单是点击事件，天然跳过，无需开关。唯一交集：剪贴板只有图片时 `readText()` 返回 `''` → `toast('剪贴板中没有文本内容')` | — |

## 需求 5：Tab 缩进（默认 4 格可设置）（M）

### 3.5.1 现状分析（含 CM6 包内实证）

- **关键现状（与预设不同）**：当前 Tab 键**不插入任何字符，焦点移出编辑器**。证据：`basicSetup`（node_modules/codemirror/dist/index.js:49-76）仅组合 `closeBracketsKeymap/defaultKeymap/searchKeymap/historyKeymap/foldKeymap/completionKeymap/lintKeymap`，**不含 `indentWithTab`**；`defaultKeymap`（@codemirror/commands/dist/index.js:1779-1793）只有 `Mod-[ → indentLess`、`Mod-] → indentMore`，**无 Tab/Shift-Tab 绑定**；`defaultTabBinding` 已被移除（commands/CHANGELOG.md:303）；`handleKeyEvents`（@codemirror/view/dist/index.js:9061-9064）无绑定命中 → 不 preventDefault → Chromium 默认把 Tab 当**焦点切换**（contentDOM 只设 contenteditable/spellcheck，view/dist/index.js:8268-8273，无 tabindex 拦截）。
  > ⚠️ 实施第一步应实测确认基线（dev 冒烟/手测）：当前按 Tab 会移焦点，这正是需求 5 要修复的真实缺口。
- **CM6 原语与默认值**：`indentUnit` Facet（@codemirror/language/dist/index.js:806-815）默认 **2 空格**（当前应用未配置 → 智能缩进按 2 空格）；`EditorState.tabSize`（@codemirror/state/dist/index.js:2890-2892）默认 **4**（`\t` 渲染宽度/列计算）；`indentMore`（commands 1601-1608）/`indentLess`（1613-1627，列感知可混删空格与 `\t`）/`insertTab`（1653-1658，无选区插 `\t`，有选区转 indentMore）/`indentWithTab`（1807，`{key:"Tab", run:indentMore, shift:indentLess}`）。应用侧 `makeState`（tabs.js:56-82）extensions = `basicSetup + lightTheme + langCompartment + wrapCompartment + matchField + updateListener`，**未配置 indentUnit/tabSize/Tab keymap**。
- **设置链路（新键接入点）**：`ALLOWED_KEYS`（settings.js:6-21，无 indentSize）+ `DEFAULTS`（23-38）+ `sanitizePatch`（110-117，非白名单键丢弃）；渲染读取 app.js:25 boot `getSettings()`；`getWordWrap` 回调模式 app.js:41 → tabs.js:51。
- **生效机制现成模板**：`setWordWrap`（tabs.js:366-372）= 闭包变量 + `wrapCompartment.reconfigure` + `activeTab.state = view.state`；`switchTab` 重放（tabs.js:179-181）防旧标签携带旧配置回退。indentSize 完全复用该模式。
- **表单模式**：app.js:468-481（scrollbarWidth number 输入 + clamp）、保存 patch app.js:572-584、保存后应用 app.js:587。
- **快捷键冲突检查**：Ctrl+Tab 已绑 `cycleTab`（app.js:709-711，document 级）；纯 Tab 是不同事件且 document 监听不拦截 → **无冲突**；`Mod-[ / Mod-]` 与 Tab/Shift-Tab 无冲突。

### 3.5.2 设计决策

| 决策点 | 决策 | 理由 |
|---|---|---|
| 设置项 | **单键 `indentSize`：number，范围 1–8，默认 4**。Tab 插入 indentSize 个空格；Shift+Tab = `indentLess` | 需求字面只要"宽度可调（2/4/8 或自定义）"；单键最小 |
| 编辑器实现 | **indentUnit/tabSize 双配置进 compartment**：`[indentUnit.of(" ".repeat(n)), EditorState.tabSize.of(n)]`——Tab/Shift+Tab/Mod-[Mod-]/Enter 智能缩进（`indentOnInput`，basicSetup 内含）统一新宽度；tabSize 同步（既有 `\t` 显示宽度与设置一致，仅视觉不改内容） | 设置语义一致 |
| Tab 命令 | **自定义 `insertIndentUnit`**（空选区 → `state.replaceSelection(state.facet(indentUnit))`；有选区/多光标 → `indentMore`；Shift → `indentLess`），比直接 `indentWithTab` 更贴合"插入缩进"（indentWithTab 只在行首加缩进，光标在行中不插入） | 主流编辑器行为 + 需求字面 |
| keymap | 静态即可：命令运行时读 `state.facet(indentUnit)`，永远取当前值，无需随设置重配；只有 indentUnit/tabSize 进 compartment | 最少重配 |
| 应用时机 | 新标签：makeState 内含 compartment（读闭包当前值）；已开标签：`setIndentSize(n)`（366-372 同款）+ `switchTab` 重放（179-181 旁） | 复用 wordWrap 双模式 |
| 多语言 | Tab/Shift+Tab 与语言无关（indentMore/indentLess 不查语言 indent service）；md/json/py 行为一致，Enter 智能缩进统一（py 4 空格约定与默认 4 一致） | — |
