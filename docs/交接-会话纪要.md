## 7. 操作纪律

- 内联 `node -e` 带中文注释会被 PowerShell 吃掉引号而**静默失败** → 一律"写 .js 文件再 node 执行"，锚点 MISS 必须报错退出。
- 改动前先 `read` 目标区域确认锚点（并发 agent 会改同一文件）。
- 委派要给"可当场验证的小交付 + 自带探针与原始输出 + 文件归属 + 谁能 build/smoke"；整包委派 ≠ 必然推进（本会话有一次三轮空转，已中止）。
- **数行数用 `[IO.File]::ReadAllLines().Count`**：`Get-Content | .Count` 会少算 5–15%（实测 `tabs.js` 1914 vs 2067、`smoke.js` 4122 vs 4368、`docmodel.js` 129 vs 151），别拿它当"行数是否变化"的判据。
- **构建是 minify 的**（`scripts/build.js` 的 `minify: true`）→ 在 `dist/bundle.js` 里 grep 函数名**不能**当作"未被接线 / 被 tree-shake"的证据（名字会被压缩重命名）。这类结论要么靠功能行为（跑冒烟），要么看非压缩产物。
- **`npm run smoke` 墙钟时间不稳定**：本会话实测 142s / 151s / 233s，另一个 agent 同一台机测到约 9 分钟（其命令通道 600s 上限曾把前台 smoke 强杀，它改用后台作业 + `job_output(wait)`，且后台跑时三个会话类用例仍全 `true`）。**只以 `E2E_RESULTS` 计数与 `SMOKE_OK` 为准**，不要用时长判断是否跑完。
- **怎么区分「慢」和「卡死」，以及卡在哪一步**（2026-08-30 19:42–19:53 实测两次真卡死）：判据 = `electron` 进程**累计 CPU 只有个位数秒**、`%TEMP%\markhunter-test-smoke` 与 `.smoke-test` **数分钟零新增写盘**、进程 `Responding=True` 且只有 1 个带标题的顶层窗口（`MarkHunter`）。
  - **定位卡点用 `.smoke-test` 最新写盘文件名反查用例**（比读被缓冲的 stdout 可靠）：两次卡死时最新文件都是 **`echo.md`**，用 `grep -n "echo\.md" scripts/smoke.js` 可定位到 **`rapidSaveEcho`（`smoke.js:796-822`）**，且该用例的收尾 `api.remove('echo.md')`（`:818`）没执行到 → **卡在 `rapidSaveEcho` 内部**。
  - **一个被证伪的假设**（记下来免得重走）：我起初推断是「被原生 `confirm()` 阻塞渲染线程」，但渲染端**根本不用原生 confirm/alert**（复核 `src/renderer/*.js` 无命中；`ui.js:177 confirmDialog` 是自绘 DOM 模态，不会阻塞 JS）→ **成因仍未知**，只能确定它是**环境相关**：同一份代码我在**前台**跑 3 次（142s / 151s / 233s）全绿并含 `rapidSaveEcho | true`，而同一时段另一个 agent 用后台/分离进程方式跑两次都停在这里。
  - 处置：`Stop-Process -Name electron -Force` → 删 `%TEMP%\markhunter-test-smoke` → 重跑（前台优先）。**若同一用例处第三次复发**，建议给 `smoke.js` 的 `step()` 加「用例开始/结束写一行带时间戳的进度日志到文件」，这样卡点可直接读、不必再靠反查文件。
  - ✅ **根因已找到（2026-08-30 20:27，我截图 + 枚举前台窗口证实）**：**前台被一个全屏游戏占用**——`GetForegroundWindow()` 标题 = `League of Legends (TM) Client`（PID 2916），MarkHunter 冒烟窗口拿不到焦点，于是 `rapidSaveEcho` 这类**依赖焦点/时序**的用例会卡住数分钟甚至永久（本次实测：20:22:00 起跑、20:23:12 写到 `echo.md` 后完全停住；我 20:21 那次前台跑也在同一用例处停了约 7 分钟后才继续）。所以之前的「环境相关」结论要精确成：**冒烟期间桌面前台不能被全屏游戏/独占全屏应用占住**（AGENTS.md 那条「后台跑会让会话类用例必挂」是同一根因的轻症）。做法：跑冒烟前先确认前台不是游戏（`GetForegroundWindow` 标题不含 `League of Legends`/其它全屏程序），若在游戏中就**别跑**——既不可信又白烧 CPU/GPU。
